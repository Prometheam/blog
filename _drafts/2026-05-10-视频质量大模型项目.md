
#### pipeline多步骤数据处理链路

   - 特征提取 pipeline：原始数据 → 预处理 → 特征计算 → 特征向量输出。比如从日志中提取关键字段、计算统计指标、生成向量等。
   - 事件分析 pipeline：事件数据 → 规则匹配/模型推理 → 结果判定 → 告警/存储。比如对事件做分类、关联、异常检测等。

拆成两条 pipeline 的好处是解耦——特征提取可以独立扩容、独立迭代，不影响事件分析的逻辑，反过来也一样。这比一条大流水线全包更灵活。

####  QBIC（Query By Image Content）是 IBM Almaden 研究中心在 1990 年代开发的图像检索系统，是早期基于内容的图像检索（CBIR）领域的开创性工作。

核心思想是不依赖文本标注，而是直接利用图像的视觉特征（颜色、纹理、形状等）进行检索。用户可以通过示例图像、草图或指定颜色/纹理特征来查询相似图像。
主要特点：

  - 颜色特征：提取图像的颜色直方图、颜色分布等
  - 纹理特征：使用粗糙度、对比度、方向性等描述纹理
  - 形状特征：提取物体的轮廓、区域形状等
  - 相似度度量：基于特征向量之间的距离计算图像相似性
    QBIC 的意义在于它证明了"以图搜图"的可行性，对后续 CBIR 领域的发展影响深远。不过受限于当时的技术水平，其检索精度和效率与现在的深度学习方法相比差距很大。

#### 华为昇腾（Ascend）是华为自研的 AI 计算平台，NPU（Neural Processing Unit，神经网络处理器）是其核心芯片架构。

  芯片产品线：

  - 昇腾 910 系列（训练场景）：910、910B、910C 等，主打大模型训练，算力对标 NVIDIA A100/H100
  - 昇腾 310 系列（推理场景）：310、310P 等，主打边缘推理和轻量计算

  加速卡产品：

  - Atlas 300 系列：PCIe 插卡形式，如 Atlas 300T（训练卡）、Atlas 300I（推理卡）
  - Atlas 训练服务器：如 Atlas 800，搭载多颗昇腾 910
  - Atlas 推理服务器：如 Atlas 500/800 推理系列

  技术架构核心：

  - 达芬奇架构（Da Vinci）：昇腾 NPU 的核心计算架构，采用 3D Cube 矩阵计算单元，专门优化矩阵乘法运算
  - CANN（Compute Architecture for Neural Networks）：异构计算架构，类似 NVIDIA 的 CUDA 生态，包括算子库、图编译器、运行时等
  - MindSpore：华为开源的深度学习框架，与昇腾硬件深度适配

  当前态势：

  受美国制裁影响，昇腾成为国内大模型训练的重要国产替代方案。多家国内厂商（如百度、讯飞等）已基于昇腾 910B/910C 进行大模型训练和推理部署。生态成熟度与 CUDA 相比仍有差距，但在持续快速迭代。

Atlas 300V 是华为昇腾系列中的视频解析加速卡，定位与 Atlas 300I（推理卡）和 300T（训练卡）不同，专门面向视频场景的 AI 推理。

  核心定位：

  视频分析专用——把视频解码、AI 推理集成在同一张卡上，减少 CPU 与加速卡之间的数据搬运，降低端到端延迟。

  主要特点：

  - 搭载昇腾 310 芯片，主打推理场景
  - 内置硬件视频解码能力（支持 H.264/H.265），可直接在卡上完成解码+推理
  - 半高半长（HLHL）PCIe 卡形态，适合密集部署
  - 典型场景：智慧交通、安防监控中同时处理几十路视频流的人脸/车辆检测识别

  与同系列对比：

```
  │    型号     │    定位     │   芯片   │       关键能力          │

  ├────────────┼────────────┼──────────┼───────────────────────┤
  │ Atlas 300I │ 推理卡      │ 昇腾 310  │ 通用 AI 推理            │
  ├────────────┼────────────┼──────────┼───────────────────────┤

```



  核心优势：

  传统方案中视频解码在 CPU 上完成，解码后的图像数据通过 PCIe 传给加速卡推理，带宽开销大。300V 把解码和推理放在同一张卡上，减少了数据搬运，提高了路数密度——同等硬件配置下能并发处理更多路视频。



#### CPU、NPU、GPU的区别

-  一、微架构层面

    CPU：深流水线（15-20+级）、乱序执行、分支预测、大容量多级缓存（L1/L2/L3）。芯片面积中控制逻辑和缓存占 60%+，ALU 占比小。核心设计目标是降低单指令延迟，追求串行性能极限。

    GPU：SIMT 执行模型，32 个线程组成一个 Warp，同一 Warp 内所有线程共享 PC，锁步执行不同数据路径。大量简单核心（SM/CU），寄存器文件极大（如 A100 每个 SM 256KB 寄存器），靠线程级并行掩盖访存延迟。芯片面积中计算单元占主导。

    NPU：以矩阵计算单元为核心（如昇腾 Da Vinci 架构的 Cube 单元），直接支持矩阵乘法指令（C=A×B），单条指令完成整个矩阵块运算。配合专用的数据搬运引擎和片上 Buffer，计算与搬运可并行。控制逻辑极简，没有分支预测和乱序执行。

    二、存储体系差异

    ```
   ┌──────────┬─────────────────────────────────┬───────────────────────────────┬──────────────────────────────────────┐
    │          │               CPU               │              GPU              │                 NPU                  │
    ├──────────┼─────────────────────────────────┼───────────────────────────────┼──────────────────────────────────────┤
    │ 缓存层次 │ L1/L2/L3 三级，容量大，延迟敏感 │ L1/L2 两级，共享 L2，带宽优先 │ 片上 Buffer（L1），软件显式管理      │
    ├──────────┼─────────────────────────────────┼───────────────────────────────┼──────────────────────────────────────┤
    │ 管理方式 │ 硬件自动管理缓存                │ 硬件管理，编程者可提示        │ 软件显式管理，程序员控制数据搬入搬出 │
    ├──────────┼─────────────────────────────────┼───────────────────────────────┼──────────────────────────────────────┤
    │ 访存哲学 │ 缓存命中为王，减少延迟          │ 合并访问，喂满带宽            │ 预取+双 Buffer，计算与搬运重叠       │
    └──────────┴─────────────────────────────────┴───────────────────────────────┴──────────────────────────────────────┘
  
    ```

  

    CPU 靠缓存降低延迟，GPU 靠合并访问提高带宽利用率，NPU 靠软件调度实现计算搬运双隐藏——三者应对"访存墙"的策略完全不同。

    三、编程模型

    - CPU：指令级并行（ILP）+ 线程级并行（TLP），编程者关注单线程性能，编译器负责指令调度
    - GPU：SIMT 模型，编程者写单线程逻辑（CUDA Thread），硬件自动将 32 线程捆绑为 Warp 执行。需要关注 Warp 分歧（Divergence）、共享内存 Bank Conflict 等
    - NPU：指令级+任务级并行。编程者需显式描述数据流（Tensor 搬入→计算→搬出），通过 CANN 的 Ascend C 或 MindSpore 编程。粒度更粗，但调度更可控

    四、计算密度与能效

    核心指标是 FLOPS/W（每瓦算力） 和 算力利用率（roofline 模型下距峰值的比例）：

    - CPU：峰值算力最低，但算术密度低的任务（不规则访存、分支密集）反而利用率高
    - GPU：峰值算力高，算术密度中等的任务（GEMM、卷积）利用率可达 60-80%
    - NPU：峰值算力高且能效最优，但只对高算术密度的矩阵运算友好，低密度任务反而不如 CPU

    五、对视频分析场景的映射

    你用 Atlas 300V 做视频分析，实际数据流是：

      1. 网络接收视频流 → CPU 处理
      2. 视频解码（H.264/H.265）→ NPU 硬件解码引擎（非 Cube 单元，是专用解码硬件）
      3. 解码帧搬入 NPU Buffer → CANN 软件调度，DMA 搬运
      4. 目标检测/识别推理 → NPU Cube 单元矩阵乘法
      5. 后处理（NMS、坐标变换）→ 视复杂度回 CPU 或留在 NPU
      6. 业务逻辑输出 → CPU

    关键瓶颈通常不在 Cube 峰值算力，而在 2→3 的数据搬运和 5 的后处理——这些地方 CPU/NPU 之间的协作效率决定整体吞吐。
