### 引言

在高性能系统中，进程间通信（IPC）的延迟直接决定系统的上限。管道和Socket虽然通用，但每次通信都要经过内核——数据从进程A拷贝到内核缓冲区，再从内核拷贝到进程B，两次拷贝的开销在高频场景下不可忽视。

共享内存（Shared Memory）是唯一可以实现**零拷贝IPC**的方案——两个进程直接读写同一块物理内存，数据传输不经过内核，延迟可以做到纳秒级。

在我参与的实时音视频系统中，编解码进程和转发进程之间就是通过共享内存+无锁Ring Buffer通信，单向延迟只有200ns。

### 2. 共享内存的两种API

#### 2.1 System V 共享内存（shmget/shmat）

```cpp
#include <sys/ipc.h>
#include <sys/shm.h>

// 创建者
int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT | 0666);
void* addr = shmat(shmid, nullptr, 0);

// 使用
memcpy(addr, "hello", 6);

// 分离和删除
shmdt(addr);
shmctl(shmid, IPC_RMID, nullptr);
```

#### 2.2 POSIX 共享内存（shm_open/mmap）— 推荐

```cpp
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

// 创建共享内存对象
int fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);  // 设置大小

// 映射到进程地址空间
void* addr = mmap(nullptr, 4096, PROT_READ | PROT_WRITE,
                  MAP_SHARED, fd, 0);
close(fd);  // 映射后fd可以关闭

// 使用（直接读写内存）
int* data = static_cast<int*>(addr);
data[0] = 42;

// 解除映射
munmap(addr, 4096);

// 删除共享内存对象
shm_unlink("/my_shm");
```

**为什么推荐POSIX？**
- 接口更现代（基于文件描述符，可以用fstat/ftruncate）
- 命名空间更清晰（`/dev/shm/`下可见文件）
- 可以与mmap无缝配合
- 支持文件系统权限控制

### 3. 同步机制：共享内存不自带同步

共享内存本身没有任何同步保护——两个进程同时读写同一块内存会产生数据竞争。需要额外的同步机制：

#### 3.1 POSIX 信号量

```cpp
#include <semaphore.h>

// 放在共享内存中的信号量
struct SharedData {
    sem_t sem;
    char data[4096];
};

// 初始化（进程间共享）
SharedData* shared = /* mmap... */;
sem_init(&shared->sem, 1, 1);  // 第二个参数=1表示进程间共享

// 生产者
sem_wait(&shared->sem);
memcpy(shared->data, msg, len);
sem_post(&shared->sem);

// 消费者
sem_wait(&shared->sem);
process(shared->data);
sem_post(&shared->sem);
```

#### 3.2 进程间互斥锁（pthread_mutex + PTHREAD_PROCESS_SHARED）

```cpp
#include <pthread.h>

struct SharedRegion {
    pthread_mutex_t mutex;
    pthread_cond_t cond;
    int data_ready;
    char buffer[8192];
};

// 初始化（必须设置PTHREAD_PROCESS_SHARED属性）
void initSharedMutex(SharedRegion* region) {
    pthread_mutexattr_t mattr;
    pthread_mutexattr_init(&mattr);
    pthread_mutexattr_setpshared(&mattr, PTHREAD_PROCESS_SHARED);
    pthread_mutexattr_setrobust(&mattr, PTHREAD_MUTEX_ROBUST);  // 健壮锁
    pthread_mutex_init(&region->mutex, &mattr);

    pthread_condattr_t cattr;
    pthread_condattr_init(&cattr);
    pthread_condattr_setpshared(&cattr, PTHREAD_PROCESS_SHARED);
    pthread_cond_init(&region->cond, &cattr);

    region->data_ready = 0;
}
```

**健壮互斥锁**：如果持锁进程崩溃，其他进程`pthread_mutex_lock`会返回`EOWNERDEAD`，然后可以调用`pthread_mutex_consistent`恢复——避免永久死锁。

#### 3.3 原子操作（最高性能，无锁）

```cpp
#include <atomic>

// 原子标志位同步（最轻量）
struct SharedBuffer {
    std::atomic<int> write_index;
    std::atomic<int> read_index;
    char data[BUFFER_SIZE];
};
// 注意：std::atomic在共享内存中使用需要 is_always_lock_free
static_assert(std::atomic<int>::is_always_lock_free);
```

### 4. 实战：共享内存无锁Ring Buffer

这是跨进程高性能通信的黄金方案——SPSC（单生产者单消费者）场景下完全无锁：

```cpp
#include <atomic>
#include <cstring>
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>

// 共享内存中的Ring Buffer布局
struct ShmRingBuffer {
    static constexpr size_t CAPACITY = 1024 * 1024;  // 1MB
    static constexpr size_t SLOT_SIZE = 256;          // 每条消息最大256字节
    static constexpr size_t SLOT_COUNT = CAPACITY / SLOT_SIZE;

    struct Slot {
        uint32_t length;               // 消息长度
        char data[SLOT_SIZE - 4];      // 消息数据
    };

    alignas(64) std::atomic<uint64_t> head;  // 消费者移动
    alignas(64) std::atomic<uint64_t> tail;  // 生产者移动
    Slot slots[SLOT_COUNT];
};

// 生产者
class ShmProducer {
public:
    ShmProducer(const char* name) {
        int fd = shm_open(name, O_CREAT | O_RDWR, 0666);
        ftruncate(fd, sizeof(ShmRingBuffer));
        ring_ = static_cast<ShmRingBuffer*>(
            mmap(nullptr, sizeof(ShmRingBuffer), PROT_READ | PROT_WRITE,
                 MAP_SHARED, fd, 0));
        close(fd);
        // 初始化
        ring_->head.store(0, std::memory_order_relaxed);
        ring_->tail.store(0, std::memory_order_relaxed);
    }

    bool write(const void* data, uint32_t len) {
        if (len > ShmRingBuffer::SLOT_SIZE - 4) return false;

        uint64_t tail = ring_->tail.load(std::memory_order_relaxed);
        uint64_t head = ring_->head.load(std::memory_order_acquire);

        // 检查是否满
        if (tail - head >= ShmRingBuffer::SLOT_COUNT) {
            return false;  // 队列满
        }

        uint64_t index = tail % ShmRingBuffer::SLOT_COUNT;
        ring_->slots[index].length = len;
        memcpy(ring_->slots[index].data, data, len);

        // release确保数据写入对消费者可见
        ring_->tail.store(tail + 1, std::memory_order_release);
        return true;
    }

private:
    ShmRingBuffer* ring_;
};

// 消费者
class ShmConsumer {
public:
    ShmConsumer(const char* name) {
        int fd = shm_open(name, O_RDWR, 0666);
        ring_ = static_cast<ShmRingBuffer*>(
            mmap(nullptr, sizeof(ShmRingBuffer), PROT_READ | PROT_WRITE,
                 MAP_SHARED, fd, 0));
        close(fd);
    }

    bool read(void* buf, uint32_t& len) {
        uint64_t head = ring_->head.load(std::memory_order_relaxed);
        uint64_t tail = ring_->tail.load(std::memory_order_acquire);

        // 检查是否空
        if (head >= tail) {
            return false;  // 队列空
        }

        uint64_t index = head % ShmRingBuffer::SLOT_COUNT;
        len = ring_->slots[index].length;
        memcpy(buf, ring_->slots[index].data, len);

        // release确保读取完成后才移动head
        ring_->head.store(head + 1, std::memory_order_release);
        return true;
    }

private:
    ShmRingBuffer* ring_;
};
```

**性能**：SPSC无锁Ring Buffer + 共享内存，单向延迟约100-300ns，吞吐可达**2000万消息/秒**。

### 5. 大块数据传输：mmap文件映射

当需要传输MB级别的大数据（如视频帧）时，拷贝到Ring Buffer代价太大。更好的方案是双Buffer翻转：

```cpp
// 双缓冲方案：生产者写Buffer A，消费者读Buffer B，然后翻转
struct DoubleBuffer {
    std::atomic<int> active_index;  // 0或1
    std::atomic<int> ready_flag;    // 数据就绪标志
    size_t frame_size;
    char buffers[2][MAX_FRAME_SIZE];
};

// 生产者：写入非活跃Buffer
void produce(DoubleBuffer* db, const void* frame, size_t size) {
    int write_idx = 1 - db->active_index.load(std::memory_order_acquire);
    memcpy(db->buffers[write_idx], frame, size);
    db->frame_size = size;
    db->active_index.store(write_idx, std::memory_order_release);
    db->ready_flag.store(1, std::memory_order_release);
}

// 消费者：读取活跃Buffer
bool consume(DoubleBuffer* db, void* buf, size_t& size) {
    if (!db->ready_flag.exchange(0, std::memory_order_acquire))
        return false;
    int read_idx = db->active_index.load(std::memory_order_acquire);
    size = db->frame_size;
    memcpy(buf, db->buffers[read_idx], size);
    return true;
}
```

### 6. 实际工程中的坑

#### 6.1 进程崩溃后的清理

```cpp
// 共享内存在进程崩溃后仍然存在（持久化在/dev/shm/）
// 需要处理"脏数据"问题

struct ShmHeader {
    uint32_t magic;            // 魔数，验证完整性
    uint32_t version;          // 版本号，防止新旧进程不兼容
    pid_t creator_pid;         // 创建者PID
    std::atomic<int> ref_count;// 引用计数
    time_t create_time;        // 创建时间
};

// 启动时检查：如果creator_pid对应的进程已不存在，说明是脏数据
bool isShmValid(ShmHeader* header) {
    if (header->magic != 0xDEADBEEF) return false;
    if (kill(header->creator_pid, 0) == -1 && errno == ESRCH) {
        // 创建者已死，共享内存是脏的
        return false;
    }
    return true;
}
```

void bindToNuma(void* addr, size_t size, int node) {

}

### 7. 共享内存 vs 其他IPC选型

| 需求 | 推荐方案 |
|------|----------|
| 延迟 < 1μs | 共享内存 + atomic |
| 吞吐 > 1000万msg/s | 共享内存 + 无锁Ring Buffer |
| 跨机器通信 | TCP/UDP Socket |
| 需要可靠性保证 | 消息队列（RabbitMQ/Kafka） |
| 简单的父子进程通信 | 管道 |
| 不同语言的进程间通信 | Unix Socket + Protocol Buffers |

### 总结

共享内存是Linux IPC中**性能的天花板**：

- **零拷贝**：数据直接在物理内存中共享，无需经过内核
- **极低延迟**：100-300ns级别，接近CPU缓存访问速度
- **极高吞吐**：千万级消息/秒

但它也是**最难正确使用**的IPC方案：需要自行处理同步（信号量/原子操作）、生命周期管理（进程崩溃清理）、内存布局（对齐/Cache Line）。

**我的建议**：只在确实需要极致性能的场景使用共享内存（如实时音视频处理、金融行情分发、高频传感器数据采集）。普通业务用Unix Socket + Protobuf就够了——代码简单可维护，性能差距在业务层面通常可忽略。
