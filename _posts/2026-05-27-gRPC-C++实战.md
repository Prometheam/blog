### 引言

gRPC是Google开源的高性能RPC框架，基于HTTP/2和Protocol Buffers。在微服务架构中，gRPC相比REST有显著优势：二进制协议更紧凑、HTTP/2多路复用更高效、强类型IDL避免接口歧义。

在我的项目中，从REST迁移到gRPC后，服务间调用延迟降低40%，带宽占用减少70%。这篇文章从C++视角系统讲解gRPC的使用和调优。

---

### 1. 为什么选gRPC？

```
REST/JSON vs gRPC/Protobuf：

  ┌──────────────┬────────────────┬───────────────────┐
  │   维度       │  REST/JSON     │  gRPC/Protobuf    │
  ├──────────────┼────────────────┼───────────────────┤
  │ 序列化       │ 文本JSON       │ 二进制Protobuf    │
  │ 传输协议     │ HTTP/1.1       │ HTTP/2            │
  │ 包大小       │ 较大（有冗余） │ 小3-10倍          │
  │ 延迟         │ 较高           │ 低40-60%          │
  │ 流式通信     │ 不原生支持     │ 原生双向流        │
  │ 代码生成     │ 需手写/Swagger │ protoc自动生成    │
  │ 类型安全     │ 弱（运行时）   │ 强（编译期）      │
  │ 浏览器兼容   │ 直接支持       │ 需要grpc-web      │
  │ 调试友好性   │ curl即可       │ 需要grpcurl       │
  └──────────────┴────────────────┴───────────────────┘
```

### 2. 服务定义（.proto文件）

```protobuf
syntax = "proto3";

package myservice;

// 消息定义
message GetUserRequest {
    int64 user_id = 1;
}

message User {
    int64 id = 1;
    string name = 2;
    string email = 3;
    int32 age = 4;
    repeated string tags = 5;
    google.protobuf.Timestamp created_at = 6;
}

message UserListResponse {
    repeated User users = 1;
    int32 total_count = 2;
}

// 服务定义：四种通信模式
service UserService {
    // 1. 一元RPC（最常用）
    rpc GetUser(GetUserRequest) returns (User);
    
    // 2. 服务端流式
    rpc ListUsers(UserListRequest) returns (stream User);
    
    // 3. 客户端流式
    rpc UploadUsers(stream User) returns (UploadResponse);
    
    // 4. 双向流式
    rpc Chat(stream ChatMessage) returns (stream ChatMessage);
}
```

生成C++代码：
```bash
protoc --grpc_out=./generated --plugin=protoc-gen-grpc=`which grpc_cpp_plugin` \
       --cpp_out=./generated myservice.proto
```

### 3. 服务端实现

#### 3.1 同步服务端（简单场景）

```cpp
#include <grpcpp/grpcpp.h>
#include "myservice.grpc.pb.h"

class UserServiceImpl final : public myservice::UserService::Service {
public:
    // 一元RPC
    grpc::Status GetUser(grpc::ServerContext* context,
                         const myservice::GetUserRequest* request,
                         myservice::User* response) override {
        // 从数据库查询用户
        auto user = db_.findUser(request->user_id());
        if (!user) {
            return grpc::Status(grpc::NOT_FOUND,
                               "User not found: " + std::to_string(request->user_id()));
        }

        response->set_id(user->id);
        response->set_name(user->name);
        response->set_email(user->email);
        return grpc::Status::OK;
    }

    // 服务端流式（分批返回大量数据）
    grpc::Status ListUsers(grpc::ServerContext* context,
                           const myservice::UserListRequest* request,
                           grpc::ServerWriter<myservice::User>* writer) override {
        auto users = db_.queryUsers(request->filter());
        for (const auto& user : users) {
            myservice::User proto_user;
            proto_user.set_id(user.id);
            proto_user.set_name(user.name);
            
            if (!writer->Write(proto_user)) {
                break;  // 客户端断开
            }
        }
        return grpc::Status::OK;
    }

    // 双向流式（实时聊天）
    grpc::Status Chat(grpc::ServerContext* context,
                      grpc::ServerReaderWriter<myservice::ChatMessage,
                                              myservice::ChatMessage>* stream) override {
        myservice::ChatMessage msg;
        while (stream->Read(&msg)) {
            // 处理收到的消息
            printf("Received: %s\n", msg.content().c_str());

            // 回复
            myservice::ChatMessage reply;
            reply.set_content("Echo: " + msg.content());
            stream->Write(reply);
        }
        return grpc::Status::OK;
    }

private:
    Database db_;
};

// 启动服务器
void runServer() {
    std::string address = "0.0.0.0:50051";
    UserServiceImpl service;

    grpc::ServerBuilder builder;
    builder.AddListeningPort(address, grpc::InsecureServerCredentials());
    builder.RegisterService(&service);

    // 性能调优
    builder.SetMaxReceiveMessageSize(64 * 1024 * 1024);  // 64MB
    builder.SetMaxSendMessageSize(64 * 1024 * 1024);
    builder.AddChannelArgument(GRPC_ARG_KEEPALIVE_TIME_MS, 10000);
    builder.AddChannelArgument(GRPC_ARG_KEEPALIVE_TIMEOUT_MS, 5000);

    std::unique_ptr<grpc::Server> server = builder.BuildAndStart();
    printf("Server listening on %s\n", address.c_str());
    server->Wait();
}
```

#### 3.2 异步服务端（高性能场景）

```cpp
// 异步服务端：用Completion Queue实现事件驱动
class AsyncUserService {
    struct CallData {
        enum State { CREATE, PROCESS, FINISH };
        
        myservice::GetUserRequest request;
        myservice::User response;
        grpc::ServerContext context;
        grpc::ServerAsyncResponseWriter<myservice::User> responder;
        State state;

        CallData(myservice::UserService::AsyncService* service,
                 grpc::ServerCompletionQueue* cq)
            : responder(&context), state(CREATE) {
            service->RequestGetUser(&context, &request, &responder, cq, cq, this);
        }

        void proceed(myservice::UserService::AsyncService* service,
                     grpc::ServerCompletionQueue* cq) {
            switch (state) {
                case CREATE:
                    state = PROCESS;
                    // 创建下一个CallData等待新请求
                    new CallData(service, cq);
                    // 处理当前请求
                    processRequest();
                    break;
                case PROCESS:
                    state = FINISH;
                    responder.Finish(response, grpc::Status::OK, this);
                    break;
                case FINISH:
                    delete this;
                    break;
            }
        }

        void processRequest() {
            response.set_id(request.user_id());
            response.set_name("User_" + std::to_string(request.user_id()));
            proceed(nullptr, nullptr);  // 直接完成
        }
    };

public:
    void run() {
        grpc::ServerBuilder builder;
        builder.AddListeningPort("0.0.0.0:50051", grpc::InsecureServerCredentials());
        builder.RegisterService(&service_);

        cq_ = builder.AddCompletionQueue();
        server_ = builder.BuildAndStart();

        // 初始化第一个CallData
        new CallData(&service_, cq_.get());

        // 事件循环
        void* tag;
        bool ok;
        while (cq_->Next(&tag, &ok)) {
            auto* call = static_cast<CallData*>(tag);
            if (ok) call->proceed(&service_, cq_.get());
            else delete call;
        }
    }

private:
    myservice::UserService::AsyncService service_;
    std::unique_ptr<grpc::ServerCompletionQueue> cq_;
    std::unique_ptr<grpc::Server> server_;
};
```

### 4. 客户端实现

```cpp
class UserClient {
public:
    UserClient(const std::string& target) {
        grpc::ChannelArguments args;
        args.SetMaxReceiveMessageSize(64 * 1024 * 1024);

        channel_ = grpc::CreateCustomChannel(
            target, grpc::InsecureChannelCredentials(), args);
        stub_ = myservice::UserService::NewStub(channel_);
    }

    // 一元调用
    std::optional<myservice::User> getUser(int64_t user_id) {
        myservice::GetUserRequest request;
        request.set_user_id(user_id);

        myservice::User response;
        grpc::ClientContext context;
        context.set_deadline(std::chrono::system_clock::now() +
                            std::chrono::seconds(5));  // 5秒超时

        grpc::Status status = stub_->GetUser(&context, request, &response);

        if (status.ok()) {
            return response;
        }
        printf("RPC failed: %s\n", status.error_message().c_str());
        return std::nullopt;
    }

    // 服务端流式接收
    std::vector<myservice::User> listUsers() {
        myservice::UserListRequest request;
        grpc::ClientContext context;

        auto reader = stub_->ListUsers(&context, request);

        std::vector<myservice::User> users;
        myservice::User user;
        while (reader->Read(&user)) {
            users.push_back(user);
        }

        grpc::Status status = reader->Finish();
        if (!status.ok()) {
            printf("Stream failed: %s\n", status.error_message().c_str());
        }
        return users;
    }

private:
    std::shared_ptr<grpc::Channel> channel_;
    std::unique_ptr<myservice::UserService::Stub> stub_;
};
```

### 5. 拦截器（Interceptor）

拦截器用于在RPC调用前后插入通用逻辑（类似中间件）：

```cpp
// 客户端拦截器：自动添加认证Token + 记录延迟
class AuthInterceptor : public grpc::experimental::Interceptor {
public:
    void Intercept(grpc::experimental::InterceptorBatchMethods* methods) override {
        if (methods->QueryInterceptionHookPoint(
                grpc::experimental::InterceptionHookPoints::PRE_SEND_INITIAL_METADATA)) {
            // 添加认证头
            auto* metadata = methods->GetSendInitialMetadata();
            metadata->insert({"authorization", "Bearer " + getToken()});

            start_time_ = std::chrono::steady_clock::now();
        }

        if (methods->QueryInterceptionHookPoint(
                grpc::experimental::InterceptionHookPoints::POST_RECV_STATUS)) {
            // 记录RPC延迟
            auto elapsed = std::chrono::steady_clock::now() - start_time_;
            auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(elapsed);
            METRICS_HISTOGRAM("grpc_client_latency_ms", ms.count());
        }

        methods->Proceed();
    }

private:
    std::chrono::steady_clock::time_point start_time_;
};

// 注册拦截器
class AuthInterceptorFactory
    : public grpc::experimental::ClientInterceptorFactoryInterface {
public:
    grpc::experimental::Interceptor* CreateClientInterceptor(
        grpc::experimental::ClientRpcInfo* info) override {
        return new AuthInterceptor();
    }
};

// 创建带拦截器的Channel
std::vector<std::unique_ptr<grpc::experimental::ClientInterceptorFactoryInterface>>
    interceptor_creators;
interceptor_creators.push_back(std::make_unique<AuthInterceptorFactory>());

auto channel = grpc::experimental::CreateCustomChannelWithInterceptors(
    "localhost:50051", grpc::InsecureChannelCredentials(), {},
    std::move(interceptor_creators));
```

### 6. 性能调优

#### 6.1 连接池

gRPC的Channel内部维护HTTP/2连接，多路复用使得单Channel可以承载大量并发RPC。但在极高并发下，单Channel可能成为瓶颈：

```cpp
class ChannelPool {
public:
    ChannelPool(const std::string& target, size_t pool_size = 4) {
        for (size_t i = 0; i < pool_size; ++i) {
            channels_.push_back(grpc::CreateChannel(
                target, grpc::InsecureChannelCredentials()));
        }
    }

    std::shared_ptr<grpc::Channel> getChannel() {
        size_t idx = next_.fetch_add(1) % channels_.size();
        return channels_[idx];
    }

private:
    std::vector<std::shared_ptr<grpc::Channel>> channels_;
    std::atomic<size_t> next_{0};
};
```

#### 6.2 关键配置参数

```cpp
grpc::ChannelArguments args;

// 连接管理
args.SetInt(GRPC_ARG_KEEPALIVE_TIME_MS, 10000);        // 每10秒发keepalive
args.SetInt(GRPC_ARG_KEEPALIVE_TIMEOUT_MS, 5000);      // keepalive超时5秒
args.SetInt(GRPC_ARG_HTTP2_MAX_PINGS_WITHOUT_DATA, 0); // 允许无数据时ping
args.SetInt(GRPC_ARG_KEEPALIVE_PERMIT_WITHOUT_CALLS, 1);

// 流控
args.SetInt(GRPC_ARG_HTTP2_STREAM_LOOKAHEAD_BYTES, 1024*1024); // 1MB预读
args.SetInt(GRPC_ARG_MAX_CONCURRENT_STREAMS, 100);

// 消息大小
args.SetMaxReceiveMessageSize(64 * 1024 * 1024);  // 64MB
args.SetMaxSendMessageSize(64 * 1024 * 1024);

// 压缩
args.SetCompressionAlgorithm(GRPC_COMPRESS_GZIP);

### 8. 何时用gRPC？

| 场景 | 推荐 | 原因 |
|------|------|------|
| 内部微服务通信 | ✅ gRPC | 性能好、类型安全、代码生成 |
| 实时流式数据 | ✅ gRPC | 原生双向流支持 |
| 对外公开API | ➡️ REST | 生态兼容性、浏览器友好 |
| 移动端通信 | ✅ gRPC | 省带宽省电 |
| 需要人工调试 | ➡️ REST | curl直接测试 |
| 多语言团队 | ✅ gRPC | proto文件统一接口定义 |

### 总结

gRPC是现代微服务间通信的事实标准。核心优势：

1. **性能**：Protobuf二进制序列化 + HTTP/2多路复用
2. **类型安全**：proto文件编译期检查，接口变更有迹可循
3. **流式通信**：原生支持服务端流、客户端流、双向流
4. **生态完善**：拦截器、负载均衡、健康检查、重试策略

**我的经验**：团队内部统一用gRPC通信，对外网关层用REST（或gRPC-Gateway自动转换）。proto文件作为"接口契约"提交到独立仓库，上下游团队通过CI/CD自动同步——这比维护一份Swagger文档靠谱得多。
