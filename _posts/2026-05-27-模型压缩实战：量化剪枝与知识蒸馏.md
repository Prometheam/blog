## 量化深度剖析

量化的本质是用低精度数据类型表示权重和激活值：

```
FP32 -> INT8 量化原理:

浮点范围 [r_min, r_max] 映射到整数 [0, 255]

量化:   q = round(r / scale) + zero_point
反量化: r = (q - zero_point) * scale

其中: scale = (r_max - r_min) / 255
      zero_point = round(-r_min / scale)

示例:
r_min = -1.0, r_max = 2.0
scale = 3.0 / 255 ≈ 0.01176
zero_point = round(1.0 / 0.01176) = 85

r = 0.5  ->  q = round(0.5/0.01176) + 85 = 128
r = -0.8 ->  q = round(-0.8/0.01176) + 85 = 17
```

**PTQ vs QAT：**

```
PTQ (Post-Training Quantization) 训练后量化:
┌──────────────┐    校准数据集     ┌─────────────┐
│ 预训练FP32模型│──────────────────>│ 量化INT8模型 │
└──────────────┘   统计激活值范围   └─────────────┘
优点: 快速，无需重新训练
缺点: 精度损失可能较大 (1-3%)

QAT (Quantization-Aware Training) 量化感知训练:
┌──────────────┐    插入伪量化节点   ┌───────────┐
│ 预训练FP32模型│──────────────────>│ QAT 微调  │
└──────────────┘                    └─────┬─────┘
                                          │ 导出
                                    ┌─────▼─────┐
                                    │ INT8 模型  │
                                    └───────────┘
优点: 精度损失小 (< 0.5%)
缺点: 需要训练数据和算力
```

**校准策略对比：**

```cpp
// 使用 CANN amct 工具进行 PTQ 量化
#include "amct_api.h"

// Per-tensor: 整个 tensor 共享一个 scale
// Per-channel: 每个输出通道独立 scale (推荐用于 Conv)
AmctConfig config;
config.set_quantize_type(AMCT_QUANT_INT8);
config.set_calibration_method(AMCT_CALIB_HISTOGRAM);  // KL散度校准
config.set_per_channel(true);  // 逐通道量化

// 校准过程: 送入100-1000张代表性数据
for (auto& batch : calibration_data) {
    amct_forward(model, batch, config);
}
amct_save_quantized_model(model, "model_int8.om");
```

**校准方法选择：**
- **MinMax**：简单快速，对异常值敏感
- **Histogram/KL散度**：统计分布后找最优截断点，精度更好
- **Percentile**：截断掉 0.01% 的极端值，鲁棒性好

## 剪枝：结构化 vs 非结构化

```
非结构化剪枝 (Fine-grained):
原始权重矩阵:          剪枝后 (稀疏):
┌─────────────────┐    ┌─────────────────┐
│ 0.3  0.1  0.8  │    │ 0.3   0   0.8  │
│ 0.02 0.5  0.01 │    │  0   0.5   0   │
│ 0.7  0.03 0.4  │    │ 0.7   0   0.4  │
└─────────────────┘    └─────────────────┘
- 灵活，压缩率高 (90%+)
- 但产生不规则稀疏，硬件难加速
- 需要专用稀疏计算库

结构化剪枝 (Structured):
原始网络:              剪枝后:
Conv: 64 filters       Conv: 32 filters (移除整个filter)
┌────────────────┐    ┌────────┐
│ F0 F1 ... F63  │    │ F0 ... F31 │
└────────────────┘    └────────┘
- 直接减少计算量，无需特殊硬件支持
- 对模型结构有影响，需要 fine-tune
```

**Magnitude Pruning 实现思路：**

```python
import torch
import torch.nn.utils.prune as prune

# 按权重绝对值大小剪枝
def magnitude_prune(model, amount=0.3):
    for name, module in model.named_modules():
        if isinstance(module, torch.nn.Conv2d):
            # 结构化剪枝: 移除 L1-norm 最小的 30% filter
            prune.ln_structured(
                module, name='weight',
                amount=amount, n=1, dim=0
            )
    return model

# Lottery Ticket Hypothesis 实现:
# 1. 随机初始化 W0, 训练得到 W_final
# 2. 按 magnitude 剪枝得到 mask M
# 3. 用 W0 * M 重新训练 -> 往往能达到原始精度!
```

**彩票假说 (Lottery Ticket Hypothesis)** 的实践意义：说明大网络中存在"中奖子网络"，找到它就能用小模型达到大模型效果。但寻找过程需要多轮训练-剪枝迭代，计算开销不小。

## 知识蒸馏

```
Teacher-Student Framework:
┌───────────────┐
│ Teacher Model │  (大模型, 高精度)
│ (ResNet-152)  │
└───────┬───────┘
        │ soft labels (softmax with T=4)
        │ [0.7, 0.2, 0.05, 0.05]  ← 携带暗知识
        ▼
┌───────────────┐
│ Student Model │  (小模型, 待学习)
│ (ResNet-18)   │
└───────┬───────┘
        │
        ▼
Loss = α * KL(soft_teacher, soft_student)    ← 蒸馏损失
     + (1-α) * CE(hard_label, student_pred)  ← 真实标签损失
```

温度 T 的作用——让 softmax 输出更"软"，暴露类间关系：

```python
# T=1 (正常): [0.95, 0.03, 0.01, 0.01]  信息量少
# T=4 (软化): [0.60, 0.20, 0.10, 0.10]  类间关系丰富

def distillation_loss(student_logits, teacher_logits, labels, T=4, alpha=0.7):
    soft_loss = F.kl_div(
        F.log_softmax(student_logits / T, dim=1),
        F.softmax(teacher_logits / T, dim=1),
        reduction='batchmean'
    ) * (T * T)  # 梯度缩放

    hard_loss = F.cross_entropy(student_logits, labels)
    return alpha * soft_loss + (1 - alpha) * hard_loss
```

**Feature Distillation（特征蒸馏）** 更进一步——不仅学输出，还学中间层特征：

```
Teacher 中间层       Student 中间层
  feature_t    ────>   feature_s
     │                     │
     └── MSE Loss ────────┘

适配器 (当维度不匹配时):
feature_s -> Conv1x1 -> 与 feature_t 对齐
```

## 昇腾部署实战

在华为昇腾 310/910 上部署量化模型的完整流程：

```bash
# 1. 使用 amct (Ascend Model Compression Toolkit) 量化
amct_onnx calibration \
    --model model_fp32.onnx \
    --data_dir ./calibration_data \
    --data_type "float32" \
    --calibration_config ./quant_config.cfg

# 2. 使用 ATC 工具转换为昇腾 .om 格式
atc --model=model_quantized.onnx \
    --framework=5 \
    --output=model_int8 \
    --soc_version=Ascend310P3 \
    --input_shape="input:1,3,224,224"

# 3. 推理部署 (ACL API)
```

## 总结

模型压缩不是简单地降低精度，而是在精度、速度、资源之间找到最优平衡点。我的经验法则：

1. **先蒸馏**：用大模型指导小模型，获取最大精度保留
2. **再剪枝**：移除冗余结构，减少计算量
3. **最后量化**：INT8 量化几乎是免费的性能提升

在昇腾生态下，amct + ATC + ACL 的工具链已经相当成熟，从模型压缩到部署上线可以做到流水线化。关键是理解每一步在做什么，才能在精度不达标时知道从哪里入手调优。
