# CThreadPool 梳理

## 一句话概括

基于 pthread 的固定/可调线程池，双队列（普通+优先），C++ 类封装 C 风格内部实现。

---

## 整体架构

```
┌─────────────────────────────────────────────┐
│              CThreadPool (对外接口)            │
│  m_threadLock (外层互斥锁，保护 m_threadPool) │
│  m_threadPool ─────────────────┐             │
└────────────────────────────────┼─────────────┘
                                 ▼
┌─────────────────────────────────────────────────────┐
│              threadpool_t (内部实现)                   │
│  lock + notify          (内层互斥锁 + 条件变量)       │
│  threads: map<pthread_t, threadpool_thread_t>        │
│  queue[] + queue_priority[]  (双循环队列)            │
│  shutdown / started    (关闭标志 / 存活线程数)        │
└─────────────────────────────────────────────────────┘
         │                         │
         ▼                         ▼
   threadpool_thread()        threadpool_task_t
   (工作线程主循环)            { function, argument }
```

---

## 核心数据结构

### threadpool_t — 线程池本体

| 字段 | 类型 | 用途 |
|------|------|------|
| lock | pthread_mutex_t | 内部数据保护 |
| notify | pthread_cond_t | 任务通知/关闭唤醒 |
| threads | map\<pthread_t, threadpool_thread_t\> | 线程ID → 状态映射 |
| queue / queue_priority | threadpool_task_t* | 普通/优先循环队列 |
| queue_head/tail/count | int | 普通队列游标和计数 |
| queue_*_priority | int | 优先队列游标和计数 |
| shutdown | int | 0=运行, 1=立即关闭, 2=优雅关闭 |
| started | int | 当前存活工作线程数 |

### threadpool_task_t — 任务

```cpp
typedef struct {
    void (*function)(void *);   // C 风格函数指针
    void *argument;              // 无类型参数
} threadpool_task_t;
```

### threadpool_thread_t — 线程状态

```cpp
typedef struct {
    pthread_t *threads;  // 线程句柄（堆分配）
    int status;          // 0=运行, 1=待退出
} threadpool_thread_t;
```

## 双层锁设计

```
调用方线程                 工作线程
    │                        │
    ▼                        ▼
lock(m_threadLock)     lock(pool->lock)
    │                        │
    ▼                        ▼
threadpool_add()       等待条件变量/取任务
    │                        │
    ▼                        ▼
unlock(m_threadLock)  unlock(pool->lock)
                             │
                             ▼
                        执行任务函数(无锁)
```

- **外层锁 m_threadLock**：保护 CThreadPool 实例，确保 threadPoolStart/Stop/AddTask 互斥
- **内层锁 pool->lock**：保护 threadpool_t 内部状态，工作线程通过条件变量等待/唤醒

## 关键流程

### 1. 启动 (threadPoolStart)

```
lock(m_threadLock)
  → threadpool_create(thread_count, queueSize)
    → new threadpool_t
    → malloc 两个循环队列 (普通 + 优先=size/2)
    → 初始化 mutex + cond
    → for i in [0, thread_count):
        malloc(pthread_t)
        pthread_create → threadpool_thread
        插入 threads map, thread_count++, started++
unlock(m_threadLock)
```

### 2. 添加任务 (threadPoolAddTask)

```
while (true) {
    lock(m_threadLock)
      → threadpool_add(pool, routine, arg, flags)
        → lock(pool->lock)
        → 判断 flags & threadpool_priority
          → 优先队列: 检查 queue_count_priority < queue_size_priority
          → 普通队列: 检查 queue_count < queue_size
        → 入队: queue[tail] = {function, argument}, tail++, count++
        → pthread_cond_signal 唤醒一个工作线程
        → unlock(pool->lock)
    unlock(m_threadLock)

    成功则 break
    失败(队列满) → 指数退避 sleep_for(20ms→100ms) 最多重试300次(~6秒)
}
```

**退避策略**：初始20ms，每次翻倍，上限100ms，最多300次。第50次打INFO日志，之后每100次打DEBUG日志。

### 3. 工作线程主循环 (threadpool_thread)

```
for (;;) {
    lock(pool->lock)

    // 等待：无任务且未关闭
    while (queue_count==0 && queue_count_priority==0 && !shutdown) {
        if (checkthreadwait() == kill) break;   // 被标记退出
        pthread_cond_wait(notify, lock)          // 释放锁，等待唤醒
    }

    if (checkthreadexit() == kill) break;         // 被标记退出
    if (immediate_shutdown) break;                // 立即关闭
    if (graceful_shutdown && 队列空) break;       // 优雅关闭

    // 取任务：优先队列优先
    if (queue_count_priority > 0)
        从优先队列头部取
    else
        从普通队列头部取

    unlock(pool->lock)

    // 执行任务（无锁）
    task.function(task.argument)
}

// 退出
started--
unlock(pool->lock)
pthread_exit(NULL)
```

### 4. 停止 (threadPoolStop)

```
lock(m_threadLock)
  → threadpool_destroy(pool, 0)
    → lock(pool->lock)
    → pool->shutdown = immediate_shutdown
    → 遍历 threads map, 标记所有 status=1
    → pthread_cond_broadcast 唤醒所有线程
    → unlock(pool->lock)
    → threadpool_free(pool)
      → 若 started > 0 则拒绝释放（返回错误）
      → free 两个队列
      → pthread_mutex_destroy / pthread_cond_destroy
      → delete pool
unlock(m_threadLock)
```

### 5. 动态调整线程数 (threadPoolSetSize)

```
lock(m_threadLock)
  → threadpool_setsize(pool, thread_count)
    → lock(pool->lock)
    → 若增大：pthread_create 新线程，插入 map
    → 若减小：遍历 map 前N个标记 status=1，broadcast 唤醒让其自行退出
    → 若相同：返回 threadpool_thread_equal
    → unlock(pool->lock)
unlock(m_threadLock)
```

## 线程退出机制

退出不是外部 kill，而是**协作式**：

1. 外部代码将 thread 状态标记为 `status=1`
2. broadcast 条件变量唤醒所有线程
3. 工作线程在两个检查点检测到 status=1：
   - `checkthreadwait()`：在 cond_wait 循环中，退出等待
   - `checkthreadexit()`：在取任务前，直接退出循环
4. 退出的线程从 map 中 erase 自己，`thread_count--`，`started--`

---

## 循环队列实现

```
queue_size = 10000 (默认)
queue_head → 最老任务位置
queue_tail → 下一个空位

入队: queue[tail] = task; tail = (tail+1) % size; count++
出队: task = queue[head]; head = (head+1) % size; count--
满:  count == size
空:  count == 0

优先队列: 同理，size = queueSize/2
```

## 高频问题

### Q1: 为什么用双层锁？

外层锁保护线程池实例的创建/销毁/调整，内层锁保护工作线程的取任务和状态变更。两层锁粒度不同：外层粗粒度，内层细粒度，工作线程执行任务时不需要外层锁。

### Q2: 双队列如何保证优先级？

工作线程取任务时先检查优先队列 `queue_count_priority > 0`，有则优先取出。因此优先任务总是先于普通任务被执行。但注意：已经在执行中的普通任务不会被抢占。

### Q3: 队列满时怎么处理？

`threadPoolAddTask` 不直接返回失败，而是指数退避重试（20ms起步，2倍增长，上限100ms，最多300次约6秒）。这是一种**调用方阻塞**策略，优点是不丢任务，缺点是调用方线程被卡住。

### Q4: 线程池如何关闭？immediate vs graceful？

- `immediate_shutdown`：立即关闭，不管队列中是否还有任务
- `graceful_shutdown`：优雅关闭，等队列中所有任务执行完再退出

两种模式都会标记所有线程 status=1 并 broadcast。区别在于工作线程主循环中检查 shutdown 值时的行为。

### Q5: 动态缩容怎么实现的？

不是直接 kill 线程，而是标记 status=1，让工作线程在下一个检查点（cond_wait醒来后或取任务前）自行退出。这是协作式退出，避免强制终止导致资源泄漏。

### Q6: 任务参数的生命周期怎么管理？

调用方 `new` 参数对象，通过 `void*` 传入；任务函数内部强转后使用，结束时 `SAFE_DELETE`。这是典型的**谁分配谁释放**模式，但完全靠约定，没有 RAII 保护。

### Q7: 已知缺陷有哪些？

1. **析构函数泄漏**：`~CThreadPool()` 仅置空指针，未调用 `threadPoolStop()`
2. **extern "C" 误用**：C 链接规范包围了 C++ 类定义，不合规
3. **threadpool_free 时序**：`started > 0` 时拒绝释放，但 destroy 中 broadcast 后立即调用 free，线程可能尚未退出
4. **checkthreadexit/checkthreadwait**：访问 `pool->threads` 时已持锁（在 pool->lock 内调用），但 erase 操作在持锁状态下修改 map，其他线程同时也在操作同一 map
5. **threadpool_setsize 减容**：遍历 map 标记 status 时在 pool->lock 内，但 erase 在工作线程的 checkthreadexit 中也操作 map，两个锁不同（外层 m_threadLock vs 内层 pool->lock）
6. **任务类型退化**：`void (*function)(void*)` 是 C 风格函数指针，无法绑定仿函数/lambda/成员函数

### Q8: 如果让你改进，会怎么做？

- 析构函数中调用 `threadPoolStop()`
- 去掉 `extern "C"` 包围
- 任务抽象改为 `std::function<void()>`，支持 lambda 和成员函数
- 用 `std::thread` + `std::condition_variable` 替代 pthread，跨平台
- 用 `std::queue` + `std::mutex` 替代手写循环队列
- 引入 RAII 管理任务参数
- destroy 中等待所有线程退出后再 free（join 语义）
