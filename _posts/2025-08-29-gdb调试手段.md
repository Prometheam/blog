<h3 style="" id="%E7%A8%8B%E5%BA%8F%E6%AD%BB%E9%94%81%E9%97%AE%E9%A2%98%E5%AE%9A%E4%BD%8D(debug%E7%89%88%E6%9C%AC%E5%BA%93%E5%8A%A0%E8%BD%BD)">程序死锁问题定位(Debug版本库加载)</h3><p style="">1.获取进程ID</p><p style=""><code>ps -ef | grep 进程名称</code></p><p style="">2.gdb调试</p><p style=""><code>gdb attach 进程ID</code></p><p style="">3.查看进程当前加载的库及其内存地址</p><p style=""><code>(gdb) info sharedlibrary</code></p><p style="">输出：</p><p style=""><code>0x00007ffff7aab000  0x00007ffff7ccd000  /usr/lib/x86_64-linux-gnu/libexample.so</code></p><p style="">记录下 libexample.so 的加载地址 <code>0x7ffff7aab000</code>**（后续替换 Debug 库时需要）。</p><p style=""><strong>或者：</strong></p><p style=""><code>cat /proc/&lt;PID&gt;/maps | grep libexample.so | grep r-xp</code></p><p style=""><code>add-symbol-file</code> 需要的是 <strong>代码段的加载基地址</strong>（即 <code>r-xp</code> 的起始地址）</p><p style="">全量输出示例</p><p style=""><code>0x7ffff7aab000 0x7ffff7acb000 r-xp  /path/to/libexample.so  # 代码段（关键！）</code></p><p style=""><code>0x7ffff7acb000 0x7ffff7ccb000 r--p  /path/to/libexample.so  # 只读数据段</code></p><p style=""><code>0x7ffff7ccb000 0x7ffff7ccf000 rw-p  /path/to/libexample.so  # 数据段</code></p><p style="">4.**强制加载 Debug 版本的符号** 覆盖现有符号</p><p style=""><code>(gdb) add-symbol-file /path/to/debug/libexample_debug.so 0x7ffff7aab000</code></p><p style="">- 此方法 <strong>不会替换内存中的代码</strong>，只是让 GDB 使用 Debug 版本的符号信息（如函数名、行号、变量等）。</p><p style="">- 如果 Debug 和 Release 库的代码布局不同（如优化导致函数地址变化），调试时可能会看到不一致的行为。</p>
