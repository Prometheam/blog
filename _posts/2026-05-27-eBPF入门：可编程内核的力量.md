### 引言

eBPF（extended Berkeley Packet Filter）是近年来Linux内核最具颠覆性的技术——它让你可以**在不修改内核源码、不加载内核模块的情况下，在内核中运行自定义代码**。

想象一下：你可以在内核的网络栈、文件系统、调度器中插入你的"探针"，实时观测系统行为、过滤网络包、做安全审计——这一切都在内核态以极高性能运行，且不会让内核崩溃（因为有验证器保证安全）。

作为后端开发者，eBPF让我们拥有了前所未有的**可观测性**和**可编程性**。Cloudflare的DDoS防护、Facebook的负载均衡（Katran）、Cilium的容器网络——都是eBPF的杰作。

### 1. eBPF 是什么？

#### 1.1 从BPF到eBPF

```
1992年：BPF（Berkeley Packet Filter）
  - 目的：高效过滤网络包（tcpdump的底层）
  - 能力：32位寄存器，有限指令集，只能读包数据
  - 限制：最多4096条指令，不能调用函数

2014年：eBPF（extended BPF）
  - 目的：通用的内核可编程框架
  - 能力：64位寄存器，丰富指令集，可调用内核helper函数
  - 扩展：不限于网络，可挂载到几乎所有内核子系统
  - 安全：验证器保证不会崩溃内核
```

### 2. eBPF 的核心组件

#### 2.1 BPF验证器（Verifier）

验证器是eBPF安全性的保证，它会在加载时检查：

```
✅ 程序必须终止（无无限循环——有限次迭代）
✅ 不能访问未初始化的寄存器
✅ 不能越界访问内存
✅ 不能有未检查的指针解引用
✅ 栈大小限制512字节
✅ 最大指令数（100万条，Linux 5.2+）
```

如果验证不通过，程序拒绝加载——**内核永远不会崩溃**。

#### 2.2 BPF Maps（数据共享）

Maps是eBPF程序与用户态之间、不同eBPF程序之间通信的唯一方式：

```
常用Map类型：
┌──────────────────┬──────────────────────────────────────┐
│ 类型             │ 用途                                 │
├──────────────────┼──────────────────────────────────────┤
│ BPF_MAP_TYPE_HASH          │ 键值对存储（最常用）   │
│ BPF_MAP_TYPE_ARRAY         │ 数组，索引访问         │
│ BPF_MAP_TYPE_RINGBUF       │ 高效事件传递到用户态   │
│ BPF_MAP_TYPE_LRU_HASH      │ 带LRU淘汰的哈希表     │
│ BPF_MAP_TYPE_PERF_EVENT_ARRAY│ 性能事件传递        │
│ BPF_MAP_TYPE_PERCPU_HASH   │ 每CPU独立的哈希表     │
└──────────────────┴──────────────────────────────────────┘
```

#### 2.3 挂载点类型

| 挂载点 | 位置 | 典型用途 |
|--------|------|----------|
| XDP | 网卡驱动层（最早） | DDoS防护、负载均衡 |
| TC | 流量控制层 | 包修改、策略路由 |
| kprobe | 任意内核函数入口 | 性能观测、调试 |
| kretprobe | 内核函数返回 | 测量函数耗时 |
| tracepoint | 内核静态追踪点 | 系统事件监控 |
| uprobe | 用户态函数入口 | 应用级追踪 |
| cgroup | cgroup操作 | 容器网络/资源控制 |
| socket | socket操作 | 包过滤 |

### 3. 快速上手：bpftrace

bpftrace是eBPF的"awk"——一行命令就能做强大的内核追踪：

#### 3.1 安装

```bash
# Ubuntu
apt install bpftrace

# CentOS/RHEL
dnf install bpftrace
```

#### 3.2 实用一行命令

```bash
# 1. 追踪所有新建的TCP连接
bpftrace -e 'kprobe:tcp_connect { printf("connect: %s → %s\n",
    ntop(((struct sock*)arg0)->__sk_common.skc_rcv_saddr),
    ntop(((struct sock*)arg0)->__sk_common.skc_daddr)); }'

# 2. 统计系统调用频率（按进程）
bpftrace -e 'tracepoint:raw_syscalls:sys_enter {
    @[comm] = count(); }'

# 3. 测量read()系统调用耗时分布
bpftrace -e 'tracepoint:syscalls:sys_enter_read { @start[tid] = nsecs; }
tracepoint:syscalls:sys_exit_read /@start[tid]/ {
    @us = hist((nsecs - @start[tid]) / 1000);
    delete(@start[tid]); }'

# 4. 追踪文件打开（看谁在打开什么文件）
bpftrace -e 'tracepoint:syscalls:sys_enter_openat {
    printf("%s open(%s)\n", comm, str(args->filename)); }'

# 5. 监控TCP重传
bpftrace -e 'kprobe:tcp_retransmit_skb {
    printf("retransmit: %s sport=%d\n", comm,
        ((struct sock*)arg0)->__sk_common.skc_num); }'

# 6. 实时统计每秒磁盘IO
bpftrace -e 'tracepoint:block:block_rq_complete {
    @bytes = sum(args->nr_sector * 512); }
    interval:s:1 { print(@bytes); clear(@bytes); }'
```

### 5. 实战：用eBPF实现网络监控

#### 5.1 统计每个IP的连接数

```c
// conn_monitor.bpf.c — eBPF内核程序
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>
#include <linux/tcp.h>

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10240);
    __type(key, __u32);      // IP地址
    __type(value, __u64);    // 连接计数
} conn_count SEC(".maps");

SEC("kprobe/tcp_v4_connect")
int trace_connect(struct pt_regs *ctx) {
    struct sock *sk = (struct sock *)PT_REGS_PARM1(ctx);
    __u32 daddr;

    bpf_probe_read_kernel(&daddr, sizeof(daddr),
                          &sk->__sk_common.skc_daddr);

    __u64 *count = bpf_map_lookup_elem(&conn_count, &daddr);
    if (count) {
        __sync_fetch_and_add(count, 1);
    } else {
        __u64 init = 1;
        bpf_map_update_elem(&conn_count, &daddr, &init, BPF_ANY);
    }

    return 0;
}

char LICENSE[] SEC("license") = "GPL";
```

用户态读取Map数据：
```c
// conn_monitor.c — 用户态程序
#include <bpf/libbpf.h>
#include <arpa/inet.h>
#include <stdio.h>
#include <unistd.h>

int main() {
    // 加载BPF程序...
    struct bpf_object *obj = bpf_object__open_file("conn_monitor.bpf.o", NULL);
    bpf_object__load(obj);

    struct bpf_program *prog = bpf_object__find_program_by_name(obj, "trace_connect");
    struct bpf_link *link = bpf_program__attach(prog);

    int map_fd = bpf_object__find_map_fd_by_name(obj, "conn_count");

    // 每秒打印连接统计
    while (1) {
        sleep(1);
        __u32 key, next_key;
        __u64 value;

        printf("\n--- Connection Count ---\n");
        key = 0;
        while (bpf_map_get_next_key(map_fd, &key, &next_key) == 0) {
            bpf_map_lookup_elem(map_fd, &next_key, &value);
            struct in_addr addr = {.s_addr = next_key};
            printf("  %s: %llu connections\n", inet_ntoa(addr), value);
            key = next_key;
        }
    }

    return 0;
}
```

#### 5.2 XDP实现简单的DDoS防护

```c
// xdp_firewall.bpf.c — 在网卡层丢弃恶意包
#include <linux/bpf.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/tcp.h>
#include <bpf/bpf_helpers.h>

// 黑名单Map
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10000);
    __type(key, __u32);      // 源IP
    __type(value, __u64);    // 丢弃计数
} blacklist SEC(".maps");

// SYN速率Map
struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_HASH);
    __uint(max_entries, 65536);
    __type(key, __u32);      // 源IP
    __type(value, __u64);    // SYN计数
} syn_count SEC(".maps");

SEC("xdp")
int xdp_firewall(struct xdp_md *ctx) {
    void *data = (void *)(long)ctx->data;
    void *data_end = (void *)(long)ctx->data_end;

    // 解析以太网头
    struct ethhdr *eth = data;
    if ((void*)(eth + 1) > data_end)
        return XDP_PASS;

    if (eth->h_proto != __constant_htons(ETH_P_IP))
        return XDP_PASS;

    // 解析IP头
    struct iphdr *ip = (void*)(eth + 1);
    if ((void*)(ip + 1) > data_end)
        return XDP_PASS;

    __u32 src_ip = ip->saddr;

    // 检查黑名单
    __u64 *blocked = bpf_map_lookup_elem(&blacklist, &src_ip);
    if (blocked) {
        __sync_fetch_and_add(blocked, 1);
        return XDP_DROP;  // 直接丢弃，不进入协议栈
    }

    // SYN Flood检测
    if (ip->protocol == IPPROTO_TCP) {
        struct tcphdr *tcp = (void*)ip + (ip->ihl * 4);
        if ((void*)(tcp + 1) > data_end)
            return XDP_PASS;

        if (tcp->syn && !tcp->ack) {
            // 这是SYN包，计数
            __u64 *count = bpf_map_lookup_elem(&syn_count, &src_ip);
            if (count) {
                __sync_fetch_and_add(count, 1);
                if (*count > 100) {  // 超过阈值，加入黑名单
                    __u64 init = 1;
                    bpf_map_update_elem(&blacklist, &src_ip, &init, BPF_ANY);
                    return XDP_DROP;
                }
            } else {
                __u64 init = 1;
                bpf_map_update_elem(&syn_count, &src_ip, &init, BPF_ANY);
            }
        }
    }

    return XDP_PASS;
}

char LICENSE[] SEC("license") = "GPL";
```

**性能**：XDP在驱动层就丢弃包，不经过内核协议栈，单核可达**26Mpps**（每秒2600万个包），比iptables快10倍以上。

### 8. 注意事项和限制

1. **内核版本**：完整功能需要Linux 5.x+，生产推荐5.10+
2. **权限要求**：需要`CAP_BPF`或root权限
3. **栈大小**：BPF栈只有512字节，不能有深递归
4. **循环限制**：必须有明确的上界（验证器要证明会终止）
5. **不能睡眠**：BPF程序不能调用可能睡眠的函数
6. **调试困难**：`bpf_printk`输出到trace_pipe，性能很差

### 总结

eBPF让Linux内核变成了一个**可编程的平台**：

- **可观测性**：不需要修改应用代码就能追踪任何内核行为
- **高性能网络**：XDP在网卡层处理包，性能远超传统iptables
- **安全审计**：实时检测异常系统调用和网络行为
- **零风险**：验证器保证BPF程序不会崩溃内核

对于后端工程师来说，eBPF是**性能排查的终极武器**——当传统工具（strace、perf、tcpdump）无法定位问题时，eBPF让你能直接在内核中"放探针"，看到任何你想看到的信息。

学习建议：从bpftrace的一行命令开始，用它解决实际的性能问题，再逐步深入到libbpf开发。不要一上来就写复杂的XDP程序——先用现成的BCC工具解决80%的问题。
