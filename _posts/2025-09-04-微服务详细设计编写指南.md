style=""><strong>3.1 技术栈</strong></p><ul><li><p style=""><strong>编程语言：</strong> Java (Spring Boot)</p></li><li><p style=""><strong>构建工具：</strong> Maven / Gradle</p></li><li><p |<br>| <code>t_order_item</code> | <code>id</code> | bigint(20) | PK | 订单项ID |<br>| | <code>order_id</code> | bigint(20) | FK | 关联订单ID |</p></li><li><p style=""><strong>索引设计：</strong> 为提高查询效率设计的索引，如为 API 接口设计</strong></h4><ul><li><p style=""><strong>4.1 公共规范</strong></p><ul><li><p style=""><strong>API网关前缀：</strong> <code>/api/order</code></p></li><li><p style=""><strong>协议：</strong> HTTP/HTTPS</p></li><li><p style=""><strong>数据格式：</strong> JSON</p></li><li><p style=""><strong>认证授权：</strong> 使用 JWT Token，通过网关统一校验，服务内可获取用户信息。</p></li><li><p style=""><strong>幂等性：</strong> 对于创建、更新等操作，提供 <code>X-Idempotency-Key</code> 请求头，防止重复提交。</p></li></ul></li><li><p style=""><strong>4.2 API 详情</strong></p><ul><li><p style="">使用 <strong>OpenAPI (Swagger)</strong> 规范来描述每个接口是<strong>最佳实践</strong>。在文档中至少提供核心接口的摘要。</p></li><li><p style=""><strong>接口1：创建订单</strong></p><ul><li><p style=""><strong>URL：</strong> <code>POST /orders</code></p></li><li><p style=""><strong>请求头：</strong> <code>Authorization: Bearer {token}</code>, <code>X-Idempotency-Key: {uuid}</code></p></li><li><p style=""><strong>请求体：</strong></p><p style=""><span style="font-size: 12px; color: var(--dsw-alias-label-primary)">json</span></p><p style=""><strong>复制</strong></p><p style=""><strong>下载</strong></p><pre><code>{
  "items": [
    {
      "productId": 123,
      "quantity": 2
    }
  ],
  "shippingAddress": "xxx"

PAID -&gt; SHIPPED -&gt; DELIVERED -&gt; CANCELLED</code></p></li></ul></li><li><p style=""><strong>5.3 异常处理与补偿机制</strong></p><ul><li><p style="">描述如何应对错误（如网络超时、服务宕机）。</p></li><li><p style=""><em>示例：调用商品服务查询库存失败，如何进行重试？扣减库存失败，如何通过定时任务或MQ进行补偿，取消订单并还原库存？</em></p></li></ul></li></ul><hr><h4 style="" id="6.-%E9%9D%9E%E5%8A%9F%E8%83%BD%E6%80%A7%E8%AE%BE%E8%AE%A1"><strong>6. 非功能性设计</strong></h4><ul><li><p style=""><strong>6.1 性能</strong></p><ul><li><p style=""><strong>目标QPS/TPS：</strong> 预计每秒处理1000个订单创建请求。</p></li><li><p style=""><strong>优化点：</strong> 数据库索引、异步处理（MQ）、缓存热点数据、数据库分库分表策略。</p></li></ul></li><li><p style=""><strong>6.2 可靠性 &amp; 高可用</strong></p><ul><li><p style="">部署至少2个实例，通过服务发现做负载均衡。</p></li><li><p style="">依赖服务（如商品服务）宕机后的熔断降级策略（使用Hystrix或Sentinel），例如：创建订单时若无法校验库存，可降级为“先创建订单，后续再异步校验库存”。</p></li></ul></li><li><p style=""><strong>6.3 可观测性</strong></p><ul><li><p style=""><strong>日志：</strong> 使用ELK栈收集和查询日志，记录关键业务日志和错误日志。</p></li><li><p style=""><strong>监控：</strong> 使用Prometheus收集指标（JVM性能、接口耗时、QPS、错误率）。</p></li><li><p style=""><strong>链路追踪：</strong> 使用SkyWalking或Zipkin集成，追踪跨服务调用链。</p></li></ul></li><li><p style=""><strong>6.4 安全性</strong></p><ul><li><p style="">接口权限控制（如：用户只能查询自己的订单）。</p></li><li><p style="">SQL防注入（使用MyBatis等ORM框架的参数化查询）。</p></li><li><p style="">敏感数据（如手机号）脱敏显示。</p></li></ul></li></ul><p style=""></p><hr><h4 style="" id="7.-%E9%83%A8%E7%BD%B2%E4%B8%8E%E8%BF%90%E7%BB%B4"><strong>7. 部署与运维</strong></h4><ul><li><p style=""><strong>7.1 环境配置</strong></p><ul><li><p style="">列出不同环境（Dev/Test/Prod）的配置项，如数据库连接、Redis地址、MQ地址。这些应放在配置中心（Nacos）中。</p></li></ul></li><li><p style=""><strong>7.2 构建与部署</strong></p><ul><li><p style=""><strong>镜像构建：</strong> 提供Dockerfile。</p></li><li><p style=""><strong>部署方式：</strong> 使用Kubernetes的Deployment和Service进行部署。</p></li><li><p style=""><strong>CI/CD流水线：</strong> 描述从代码提交到自动构建、测试、部署的流程（Jenkins/GitLab CI）。</p></li></ul></li><li><p style=""><strong>7.3 启动与健康检查</strong></p><ul><li><p style="">提供健康检查端点：<code>/actuator/health</code>。</p></li></ul></li></ul><hr><h4 style="" id="8.-%E5%BE%85%E5%AE%9A%E9%97%AE%E9%A2%98-%26-%E6%9C%AA%E6%9D%A5%E8%80%83%E9%87%8F"><strong>8. 待定问题 &amp;
