### 引言

日志是后端服务的"黑匣子"——线上问题排查全靠它。但日志也是性能杀手：同步写磁盘一次需要几十微秒，如果每条消息都打日志，吞吐量直接腰斩。

在我的项目中，曾因为日志系统设计不当导致P99延迟飙升——一次磁盘flush阻塞了IO线程15ms。今天分享如何设计一个百万QPS级别的异步日志系统。

---

### 1. 日志系统的核心矛盾

```
矛盾：可靠性 vs 性能

  同步写盘：每条日志立即flush
    ✅ 不丢日志（crash也不丢）
    ❌ 延迟高（fsync ≈ 50~200μs/NVMe, 5~15ms/HDD）
    ❌ 吞吐低（受限于磁盘IOPS）

  异步写盘：缓冲 → 批量写入
    ✅ 高吞吐（百万条/秒）
    ✅ 低延迟（写入缓冲区 ≈ 100ns）
    ❌ crash可能丢失最近几秒的日志
```

**工程选择**：绝大多数场景选异步。只有审计日志等对完整性要求极高的场景才用同步。

---

### 2. 异步日志架构

```
业务线程 (多个)           日志后端线程 (1个)
    │                         │
    │ log("msg")              │
    │    ↓                    │
    │ 格式化 → 写入前端Buffer │
    │    ↓                    │
    │ notify()  ────────────→ │ 唤醒
    │                         │ swap(前端Buffer, 后端Buffer)
    │                         │ write(后端Buffer → 文件)
    │                         │ 可选：定时flush
    │                         │
    │ 继续业务逻辑（不等待）   │
```

**关键设计**：
- 前端（写入）：格式化+写缓冲，尽量无锁
- 后端（输出）：独立线程批量写文件
- 前后端通过**双缓冲交换**解耦

### 3. 双缓冲（Double Buffering）

muduo日志库的经典设计：

```cpp
class AsyncLogger {
public:
    AsyncLogger(const std::string& filename, size_t rollSize)
        : filename_(filename), rollSize_(rollSize),
          currentBuffer_(new Buffer), nextBuffer_(new Buffer),
          running_(true), thread_([this] { backendLoop(); }) {}

    ~AsyncLogger() {
        running_ = false;
        cv_.notify_one();
        thread_.join();
    }

    // 前端：业务线程调用（可能多线程并发）
    void append(const char* logline, size_t len) {
        std::lock_guard<std::mutex> lock(mutex_);
        if (currentBuffer_->avail() > len) {
            currentBuffer_->append(logline, len);
        } else {
            // 当前Buffer满了，放入待写队列
            buffers_.push_back(std::move(currentBuffer_));

            if (nextBuffer_) {
                currentBuffer_ = std::move(nextBuffer_);  // 使用预备Buffer
            } else {
                currentBuffer_.reset(new Buffer);  // 罕见：前端太快
            }

            currentBuffer_->append(logline, len);
            cv_.notify_one();  // 通知后端线程
        }
    }

private:
    using Buffer = FixedBuffer<4 * 1024 * 1024>;  // 4MB缓冲区
    using BufferPtr = std::unique_ptr<Buffer>;
    using BufferVec = std::vector<BufferPtr>;

    // 后端：独立线程写文件
    void backendLoop() {
        BufferPtr newBuffer1(new Buffer);
        BufferPtr newBuffer2(new Buffer);
        BufferVec buffersToWrite;

        while (running_) {
            {
                std::unique_lock<std::mutex> lock(mutex_);
                if (buffers_.empty()) {
                    cv_.wait_for(lock, std::chrono::seconds(3));  // 最多等3秒
                }
                buffers_.push_back(std::move(currentBuffer_));
                currentBuffer_ = std::move(newBuffer1);
                buffersToWrite.swap(buffers_);
                if (!nextBuffer_) {
                    nextBuffer_ = std::move(newBuffer2);
                }
            }

            // 临界区外：写文件（不持锁！）
            for (const auto& buf : buffersToWrite) {
                output_.append(buf->data(), buf->length());
            }
            output_.flush();

            // 回收Buffer
            if (buffersToWrite.size() > 2) {
                buffersToWrite.resize(2);  // 丢弃多余的Buffer
            }
            if (!newBuffer1) {
                newBuffer1 = std::move(buffersToWrite.back());
                buffersToWrite.pop_back();
                newBuffer1->reset();
            }
            if (!newBuffer2) {
                newBuffer2 = std::move(buffersToWrite.back());
                buffersToWrite.pop_back();
                newBuffer2->reset();
            }
            buffersToWrite.clear();
        }
    }

    std::string filename_;
    size_t rollSize_;
    BufferPtr currentBuffer_;
    BufferPtr nextBuffer_;
    BufferVec buffers_;
    std::mutex mutex_;
    std::condition_variable cv_;
    std::atomic<bool> running_;
    std::thread thread_;
    LogFile output_;
};
```

**性能数据**：
- 前端append：~100ns（只是memcpy到Buffer）
- 后端写盘：批量write，单次写入几MB，摊销极低
- 吞吐量：**200万条/秒**（单线程写入）

### 4. 日志格式化优化

格式化（sprintf/fmt）往往比写缓冲还慢。优化手段：

```cpp
// ❌ 慢：std::stringstream
std::ostringstream oss;
oss << timestamp << " [" << level << "] " << file << ":" << line << " " << msg;

// ✅ 快：直接写入固定缓冲区
class LogStream {
    char buf_[4096];
    size_t pos_ = 0;

public:
    LogStream& operator<<(int val) {
        pos_ += snprintf(buf_ + pos_, sizeof(buf_) - pos_, "%d", val);
        return *this;
    }
    LogStream& operator<<(const char* s) {
        size_t len = strlen(s);
        memcpy(buf_ + pos_, s, len);
        pos_ += len;
        return *this;
    }
    // ...更多类型重载
};

// ✅ 更快：编译期格式化（fmt/spdlog方式）
// spdlog内部使用fmt库，格式化速度比printf快3-5倍
spdlog::info("User {} logged in from {}", user_id, ip);
```

### 5. 日志切割（Log Rolling）

```cpp
class RollingFile {
    std::string basename_;
    size_t roll_size_;           // 单文件最大大小
    size_t bytes_written_ = 0;
    FILE* fp_ = nullptr;
    int file_count_ = 0;

public:
    RollingFile(const std::string& basename, size_t rollSize)
        : basename_(basename), roll_size_(rollSize) {
        rollFile();
    }

    void append(const char* data, size_t len) {
        fwrite(data, 1, len, fp_);
        bytes_written_ += len;
        if (bytes_written_ > roll_size_) {
            rollFile();
        }
    }

    void flush() { fflush(fp_); }

private:
    void rollFile() {
        if (fp_) fclose(fp_);
        // 文件名格式: myservice.20260527-143052.0.log
        auto now = std::chrono::system_clock::now();
        std::string filename = basename_ + "." + formatTime(now) + "."
                             + std::to_string(file_count_++) + ".log";
        fp_ = fopen(filename.c_str(), "w");
        bytes_written_ = 0;
    }
};
```

### 6. spdlog：工业级方案

实际项目中推荐直接用spdlog——它实现了上述所有优化：

```cpp
#include <spdlog/spdlog.h>
#include <spdlog/sinks/rotating_file_sink.h>
#include <spdlog/async.h>

void setupLogger() {
    // 异步日志 + 文件切割
    spdlog::init_thread_pool(8192, 1);  // 队列8192条，1个后端线程
    
    auto sink = std::make_shared<spdlog::sinks::rotating_file_sink_mt>(
        "logs/myservice.log",
        50 * 1024 * 1024,  // 50MB per file
        10                  // keep 10 files
    );

    auto logger = std::make_shared<spdlog::async_logger>(
        "main", sink,
        spdlog::thread_pool(),
        spdlog::async_overflow_policy::overrun_oldest  // 队列满时丢弃最旧的
    );

    logger->set_pattern("[%Y-%m-%d %H:%M:%S.%e] [%l] [%t] %v");
    logger->set_level(spdlog::level::info);
    spdlog::set_default_logger(logger);
}

// 使用
spdlog::info("Connection from {}:{}, fd={}", ip, port, fd);
spdlog::warn("Slow query: {}ms, sql={}", elapsed_ms, sql);
spdlog::error("Failed to connect to Redis: {}", error_msg);
```

### 7. 设计决策总结

| 决策点 | 选择 | 原因 |
|--------|------|------|
| 同步/异步 | 异步 | 性能差100倍 |
| 缓冲策略 | 双缓冲swap | 前后端最大程度解耦 |
| 队列满策略 | 丢弃最旧 | 避免阻塞业务线程 |
| 格式化方式 | fmt/spdlog | 比printf快3-5倍 |
| 文件切割 | 按大小(50MB) | 便于传输和清理 |
| flush频率 | 每3秒或Buffer满 | 平衡可靠性和性能 |

---

### 总结

高性能日志系统的核心是**前后端分离 + 批量IO**：

1. 前端只做格式化+写缓冲（纳秒级，不阻塞业务）
2. 后端独立线程批量写文件（微秒级，摊销到每条日志几乎零开销）
3. 双缓冲交换实现前后端无阻塞解耦

生产环境直接用**spdlog**——它已经把这些优化做到了极致，单线程吞吐200万条/秒，没有必要再造轮子。
