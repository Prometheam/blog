<p style="">malloc 的底层实现依赖于 C 库，通常使用 ptmalloc（glibc 默认分配器）、tcmalloc（Google）或 jemalloc（FreeBSD 等）等。</p><p style="">下文详细阐述 glibc 的 ptmalloc 机制下的 malloc 的底层实现</p><hr><h2 style="" id="%E5%9F%BA%E6%9C%AC%E6%A6%82%E5%BF%B5">基本概念</h2><p style="text-indent: 2em">内存分配器：管理堆内存，处理内存的分配和释放。</p><p style="text-indent: 2em">块（Chunk）：内存分配的基本单位，每个分配的内存块都有一个头部的元数据。</p><p style="text-indent: 2em">空闲链表（Free List）：用于管理空闲块，常见的有单向链表和双向链表。</p><p style="text-indent: 2em">箱（Bins）：用于存放不同大小的空闲块，提高分配效率。</p><h2 style="" id="%E5%86%85%E5%AD%98%E5%B8%83%E5%B1%80">内存布局</h2><p style="text-indent: 2em">在 glibc 中，malloc 管理的内存通常通过 brk 或 mmap 系统调用从操作系统获取。</p><ul><li><p style="">brk：扩展堆的顶部，用于较小内存分配。</p></li><li><p style="">mmap：创建匿名内存映射，用于大内存分配（通常超过 MMAP_THRESHOLD，默认为 128KB）。</p></li></ul><p style=""></p><h2 style="" id="%E5%9D%97%EF%BC%88chunk%EF%BC%89%E7%BB%93%E6%9E%84">块（Chunk）结构</h2><p style="">每个内存块（包括已分配和空闲的）都有一个头部的元数据，定义如下：</p><pre><code>struct malloc_chunk {
  size_t      prev_size;  /* 前一个块的大小（如果前一个块是空闲的） */
  size_t      size;       /* 当前块的大小和状态标志 */

  struct malloc_chunk* fd; /* 双向链表的前驱指针（仅空闲块有效） */
  struct malloc_chunk* bk; /* 双向链表的后继指针（仅空闲块有效） */
};</code></pre><ul><li><p style=""><strong>prev_size</strong>：如果前一个块是空闲的，这个字段存储前一个块的大小；如果前一个块是已分配的，则这个字段可以被前一个块使用（作为用户数据的一部分）。</p></li><li><p style=""><strong>size</strong>：当前块的大小，由于内存对齐，大小的低3位用作标志位：</p><ul><li><p style=""><code>PREV_INUSE</code> (最低位)：前一个块是否已分配。</p></li><li><p style=""><code>IS_MMAPPED</code> (次低位)：当前块是否通过 <code>mmap</code> 分配。</p></li><li><p style=""><code>NON_MAIN_ARENA</code> (第三位)：是否不属于主分配区。</p></li></ul></li></ul><h2 style="" id="%E7%A9%BA%E9%97%B2%E5%9D%97%E7%AE%A1%E7%90%86">空闲块管理</h2><p style="">空闲块通过双向链表连接，这些链表称为“bins”。ptmalloc 有多种类型的 bins：</p><ol><li><p style=""><strong>Fast bins</strong>：单向链表，管理小内存块（默认小于 64B），后进先出，不合并空闲块。</p></li><li><p style=""><strong>Small bins</strong>：双向链表，管理小于 512B 的块，每个 bin 中的块大小相同，先进先出。</p></li><li><p style=""><strong>Large bins</strong>：双向链表，管理大于等于 512B 的块，每个 bin 中的块大小在一个范围内，按大小排序。</p></li><li><p style=""><strong>Unsorted bin</strong>：双向链表，存放刚刚释放的块，用于快速重新分配。</p></li></ol><h2 style="" id="%E5%88%86%E9%85%8D%E6%B5%81%E7%A8%8B">分配流程</h2><ol><li><p style=""><strong>小内存分配（&lt; 64B）</strong>：</p><ul><li><p style="">首先在 fast bins 中查找对应大小的空闲块。</p></li><li><p style="">如果找到，则取出并返回。</p></li></ul></li><li><p style=""><strong>中等内存分配（64B ~ 512B）</strong>：</p><ul><li><p style="">在 small bins 中查找。</p></li><li><p style="">如果 small bin 为空，则从 unsorted bin 中查找并分割。</p></li></ul></li><li><p style=""><strong>大内存分配（&gt;= 512B）</strong>：</p><ul><li><p style="">在 large bins 中查找最合适的块。</p></li><li><p style="">如果找不到，则从更大的 large bin 中分割，或者从 top chunk 分割。</p></li></ul></li><li><p style=""><strong>如果上述步骤都失败</strong>：</p><ul><li><p style="">扩展 top chunk（通过 <code>brk</code> 或 <code>mmap</code>）并从中分配。</p></li><li><p style="">如果需要分配的内存很大（超过 <code>MMAP_THRESHOLD</code>），则直接使用 <code>mmap</code> 分配。</p></li></ul></li></ol><h2 style="" id="%E9%87%8A%E6%94%BE%E6%B5%81%E7%A8%8B">释放流程</h2><ol><li><p style=""><strong>检查前后块是否空闲</strong>，如果空闲则合并，避免碎片。</p></li><li><p style=""><strong>放入 unsorted bin</strong>，以便下次分配时快速重用。</p></li><li><p style=""><strong>如果块大小适合 fast bin</strong>，则放入 fast bin（不合并）。</p></li></ol><p style=""></p><h2 style="" id="1.-malloc-%E7%9A%84%E5%9F%BA%E6%9C%AC%E6%B5%81%E7%A8%8B"><strong>1. </strong><code>malloc</code><strong> 的基本流程</strong></h2><p style="line-height: 1.6">当调用 <code>malloc(size)</code> 时，底层会执行以下操作：</p><ol><li><p style=""><strong>检查请求大小</strong>：</p><ul><li><p style="">若 <code>size == 0</code>，可能返回 <code>NULL</code> 或一个特殊指针（依赖实现）。</p></li><li><p style="">若 <code>size</code> 过大（如超过 <code>MMAP_THRESHOLD</code>，默认通常为 128KB），直接使用 <code>mmap</code> 分配。</p></li></ul></li><li><p style=""><strong>从空闲内存链表中查找</strong>：</p><ul><li><p style="">在堆内存的空闲块（<code>free list</code>）中搜索足够大的内存块。</p></li><li><p style="">使用算法（如 <code>ptmalloc</code> 的隐式链表或显式链表）匹配最佳块。</p></li></ul></li><li><p style=""><strong>分割或分配新内存</strong>：</p><ul><li><p style="">若找到的块比需求大，可能分割剩余部分放回空闲链表。</p></li><li><p style="">若没有足够空间，调用 <code>sbrk</code> 或 <code>mmap</code> 向操作系统申请更多内存。</p></li></ul></li><li><p style=""><strong>返回内存地址</strong>：</p><ul><li><p style="">返回分配的内存地址（通常位于堆区），用户可通过指针访问。</p></li></ul></li></ol><hr><h2 style="" id="2.-%E5%BA%95%E5%B1%82%E5%86%85%E5%AD%98%E5%88%86%E9%85%8D%E6%96%B9%E5%BC%8F"><strong>2. 底层内存分配方式</strong></h2><p style="line-height: 1.6"><code>malloc</code> 最终依赖两种系统调用分配内存：</p><h3 style="" id="(1)-brk%2Fsbrk%EF%BC%88%E5%B0%8F%E5%86%85%E5%AD%98%E5%88%86%E9%85%8D%EF%BC%89"><strong>(1) </strong><code>brk</code><strong>/</strong><code>sbrk</code><strong>（小内存分配）</strong></h3><ul><li><p style=""><strong>原理</strong>：通过移动堆顶指针（<code>program break</code>）扩展堆内存。</p></li><li><p style=""><strong>特点</strong>：</p><ul><li><p style="">适用于小内存请求（如 <code>&lt; 128KB</code>）。</p></li><li><p style="">分配速度快，但频繁调用可能导致内存碎片。</p></li></ul></li><li><p style=""><strong>示例</strong>：</p><p style="">c复制代码</p><pre><code class="language-c">void *malloc(size_t size) {
    if (size &lt;= MMAP_THRESHOLD) {
        return sbrk(size);  // 扩展堆空间
    }
    // ...
}</code></pre></li></ul><h3 style="" id="(2)-mmap%EF%BC%88%E5%A4%A7%E5%86%85%E5%AD%98%E5%88%86%E9%85%8D%EF%BC%89"><strong>(2) </strong><code>mmap</code><strong>（大内存分配）</strong></h3><ul><li><p style=""><strong>原理</strong>：直接映射匿名内存页到进程地址空间（不依赖堆）。</p></li><li><p style=""><strong>特点</strong>：</p><ul><li><p style="">适用于大内存请求（如 <code>&gt;= 128KB</code>）。</p></li><li><p style="">避免堆碎片，但系统调用开销较大。</p></li></ul></li><li><p style=""><strong>示例</strong>：</p><p style="">c复制代码</p><pre><code class="language-c">void *malloc(size_t size) {
    if (size &gt;= MMAP_THRESHOLD) {
        return mmap(NULL, size, PROT_READ | PROT_WRITE, 
                   MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    }
    // ...
}</code></pre></li></ul><hr><h2 style="" id="3.-%E5%86%85%E5%AD%98%E7%AE%A1%E7%90%86%E7%AE%97%E6%B3%95"><strong>3. 内存管理算法</strong></h2><p style="line-height: 1.6">不同 <code>malloc</code> 实现（如 <code>glibc</code> 的 <code>ptmalloc</code>、<code>jemalloc</code>、<code>tcmalloc</code>）使用不同算法优化性能：</p><h3 style="" id="(1)-ptmalloc%EF%BC%88glibc-%E9%BB%98%E8%AE%A4%EF%BC%89"><strong>(1) </strong><code>ptmalloc</code><strong>（glibc 默认）</strong></h3><ul><li><p style=""><strong>空闲链表（Bins）</strong>：</p><ul><li><p style="">将空闲块按大小分类（如 <code>fast bins</code>、<code>small bins</code>、<code>large bins</code>）。</p></li><li><p style="">快速匹配小内存请求，减少搜索时间。</p></li></ul></li><li><p style=""><strong>线程本地缓存（</strong><code>tcache</code><strong>）</strong>：</p><ul><li><p style="">每个线程维护独立的内存池，避免全局锁竞争。</p></li></ul></li></ul><h3 style="" id="(2)-jemalloc%EF%BC%88facebook%2Ffreebsd%EF%BC%89"><strong>(2) </strong><code>jemalloc</code><strong>（Facebook/FreeBSD）</strong></h3><ul><li><p style=""><strong>多级内存池</strong>：</p><ul><li><p style="">按线程和大小分层管理，减少碎片和锁冲突。</p></li></ul></li><li><p style=""><strong>适用于高并发场景</strong>。</p></li></ul><h3 style="" id="(3)-tcmalloc%EF%BC%88google%EF%BC%89"><strong>(3) </strong><code>tcmalloc</code><strong>（Google）</strong></h3><ul><li><p style=""><strong>线程缓存 + 全局缓存</strong>：</p><ul><li><p style="">小对象优先从线程缓存分配，大对象走全局堆。</p></li></ul></li><li><p style=""><strong>减少锁争用</strong>，适合多线程应用。</p></li></ul><hr><h2 style="" id="4.-%E5%86%85%E5%AD%98%E7%A2%8E%E7%89%87%E9%97%AE%E9%A2%98"><strong>4. 内存碎片问题</strong></h2><h3 style="" id="(1)-%E5%86%85%E9%83%A8%E7%A2%8E%E7%89%87"><strong>(1) 内部碎片</strong></h3><ul><li><p style=""><strong>原因</strong>：分配的内存块比实际需求大（如对齐填充）。</p></li><li><p style=""><strong>示例</strong>：请求 10B，但分配 16B（因对齐要求）。</p></li></ul><h3 style="" id="(2)-%E5%A4%96%E9%83%A8%E7%A2%8E%E7%89%87"><strong>(2) 外部碎片</strong></h3><ul><li><p style=""><strong>原因</strong>：频繁分配/释放导致内存块分散，无法合并成大块。</p></li><li><p style=""><strong>解决方案</strong>：</p><ul><li><p style="">合并相邻空闲块（<code>coalescing</code>）。</p></li><li><p style="">使用 <code>mmap</code> 分配大块内存避免堆碎片。</p></li></ul></li></ul><hr><h2 style="" id="5.-free-%E7%9A%84%E5%B7%A5%E4%BD%9C%E5%8E%9F%E7%90%86"><strong>5. </strong><code>free</code><strong> 的工作原理</strong></h2><p style="line-height: 1.6">调用 <code>free(ptr)</code> 时：</p><ol><li><p style=""><strong>检查指针有效性</strong>：若 <code>ptr == NULL</code>，直接返回。</p></li><li><p style=""><strong>判断内存来源</strong>：</p><ul><li><p style="">若来自 <code>mmap</code>，直接调用 <code>munmap</code> 释放。</p></li><li><p style="">若来自堆，将内存块标记为空闲并放回链表（可能合并相邻块）。</p></li></ul></li><li><p style=""><strong>延迟归还操作系统</strong>：</p><ul><li><p style="">空闲内存可能保留在进程堆中，供后续 <code>malloc</code> 复用，而非立即归还系统（通过 <code>M_TRIM_THRESHOLD</code> 控制）。<img src="/upload/image-obMn.png" width="100%" height="100%" style="display: inline-block"></p></li></ul></li></ol><hr><h2 style="" id="6.-%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96%E5%BB%BA%E8%AE%AE"><strong>6. 性能优化建议</strong></h2><ol><li><p style=""><strong>避免频繁小内存分配</strong>：</p><ul><li><p style="">预分配大块内存，自行管理（如对象池）。</p></li></ul></li><li><p style=""><strong>选择合适分配器</strong>：</p><ul><li><p style="">多线程应用优先用 <code>jemalloc</code> 或 <code>tcmalloc</code>。</p></li></ul></li><li><p style=""><strong>监控内存使用</strong>：</p><ul><li><p style="">工具：<code>valgrind</code>、<code>malloc_stats()</code>、<code>pmap</code>。</p></li></ul></li></ol><p style=""></p>
