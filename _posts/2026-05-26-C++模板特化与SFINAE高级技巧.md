做了九年C++后端开发，模板元编程是我日常工具箱中最锋利的那把刀。今天系统梳理一下模板特化与SFINAE的高级用法，这些技巧在写通用库和框架时几乎不可避免。

## 全特化与偏特化

模板特化分两种：全特化（Full Specialization）为所有模板参数提供具体类型；偏特化（Partial Specialization）只固定部分参数。

```cpp
// 主模板
template <typename T, typename U>
struct Converter {
    static std::string to_string(const T& val) {
        return "generic";
    }
};

// 全特化：T=int, U=std::string
template <>
struct Converter<int, std::string> {
    static std::string to_string(const int& val) {
        return std::to_string(val);
    }
};

// 偏特化：T为任意指针类型
template <typename T, typename U>
struct Converter<T*, U> {
    static std::string to_string(T* const& val) {
        return val ? Converter<T, U>::to_string(*val) : "null";
    }
};
```

编译器选择特化版本的优先级：全特化 > 偏特化 > 主模板。注意函数模板不支持偏特化，只能用重载来模拟。

## SFINAE原理

SFINAE（Substitution Failure Is Not An Error）的核心思想：当编译器用实参替换模板形参时，如果产生了无效的类型或表达式，该候选不会导致编译错误，只是被静默丢弃。

```
模板实参替换流程：
┌─────────────────────┐
│ 候选函数模板集合      │
└──────────┬──────────┘
           │ 逐个替换模板参数
           ▼
┌─────────────────────┐
│ 替换成功？           │──── 否 ──→ 丢弃（SFINAE）
└──────────┬──────────┘
           │ 是
           ▼
┌─────────────────────┐
│ 加入重载决议集合      │
└──────────┬──────────┘
           │ 选择最佳匹配
           ▼
┌─────────────────────┐
│ 调用选中的函数        │
└─────────────────────┘
```

## std::enable_if的三种用法

`enable_if`是SFINAE最常用的工具，本质就是条件满足时提供一个类型，不满足时替换失败。

```cpp
// 方式1：作为返回类型
template <typename T>
typename std::enable_if<std::is_integral<T>::value, T>::type
safe_divide(T a, T b) {
    return b != 0 ? a / b : 0;
}

// 方式2：作为额外模板参数（推荐，不污染签名）
template <typename T,
          typename = std::enable_if_t<std::is_floating_point_v<T>>>
T safe_divide(T a, T b) {
    return std::abs(b) > 1e-10 ? a / b : T{0};
}

// 方式3：作为函数参数默认值
template <typename T>
void process(T val,
             std::enable_if_t<std::is_class_v<T>>* = nullptr) {
    val.do_something();
}
```

## Expression SFINAE

C++11引入的表达式SFINAE更加灵活，通过`decltype`和`declval`检测表达式是否合法：

```cpp
// 检测类型是否有serialize()成员函数
template <typename T>
auto has_serialize_impl(int)
    -> decltype(std::declval<T>().serialize(), std::true_type{});

template <typename T>
auto has_serialize_impl(...) -> std::false_type;

template <typename T>
using has_serialize = decltype(has_serialize_impl<T>(0));
```

这里用`int`和`...`的重载优先级差异来实现分发：如果`T`有`serialize()`方法，第一个重载匹配成功（`int`优先于`...`）；否则SFINAE掉第一个，退回到`...`版本。

## if constexpr vs SFINAE

C++17的`if constexpr`在很多场景下可以替代SFINAE，代码更直观：

```cpp
// SFINAE写法（C++11/14）
template <typename T>
std::enable_if_t<std::is_integral_v<T>, std::string>
to_json(const T& val) { return std::to_string(val); }

template <typename T>
std::enable_if_t<std::is_floating_point_v<T>, std::string>
to_json(const T& val) { return std::to_string(val); }

// if constexpr写法（C++17，更清晰）
template <typename T>
std::string to_json(const T& val) {
    if constexpr (std::is_integral_v<T>) {
        return std::to_string(val);
    } else if constexpr (std::is_floating_point_v<T>) {
        return std::to_string(val);
    } else if constexpr (has_serialize<T>::value) {
        return val.serialize();
    } else {
        static_assert(always_false<T>, "Unsupported type");
    }
}
```

选择建议：函数内部分支用`if constexpr`；需要控制重载集合、影响函数签名时仍用SFINAE。

## Tag Dispatch模式

Tag Dispatch是SFINAE的替代方案，通过类型标签进行函数分发：

```cpp
namespace detail {
    template <typename Iter>
    void advance_impl(Iter& it, int n, std::random_access_iterator_tag) {
        it += n;  // O(1)
    }
    template <typename Iter>
    void advance_impl(Iter& it, int n, std::input_iterator_tag) {
        while (n-- > 0) ++it;  // O(n)
    }
}

template <typename Iter>
void advance(Iter& it, int n) {
    detail::advance_impl(it, n,
        typename std::iterator_traits<Iter>::iterator_category{});
}
```

Tag Dispatch的优势是编译错误信息更清晰，而且不同实现分离在不同函数中，可读性好。

## 实战：通用序列化分发

综合运用上述技巧，实现一个根据类型特征自动选择序列化策略的框架：

```cpp
// 类型特征检测
template <typename T, typename = void>
struct has_to_json : std::false_type {};

template <typename T>
struct has_to_json<T,
    std::void_t<decltype(std::declval<T>().to_json())>>
    : std::true_type {};

// 通用序列化器
template <typename T>
std::string serialize(const T& obj) {
    if constexpr (std::is_arithmetic_v<T>) {
        return std::to_string(obj);
    } else if constexpr (std::is_same_v<T, std::string>) {
        return "\"" + obj + "\"";
    } else if constexpr (has_to_json<T>::value) {
        return obj.to_json();
    } else if constexpr (is_container_v<T>) {
        std::string result = "[";
        for (auto it = obj.begin(); it != obj.end(); ++it) {
            if (it != obj.begin()) result += ",";
            result += serialize(*it);
        }
        return result + "]";
    }
}
```

这种设计的好处是：新增类型支持时只需要添加一个`if constexpr`分支或特化一个trait，不需要修改已有代码，完美符合开闭原则。

## 小结

模板特化和SFINAE是C++泛型编程的核心机制。在实际项目中，我的经验是：优先用`if constexpr`处理简单分支，用`std::void_t`配合Expression SFINAE检测类型能力，用Tag Dispatch处理需要清晰分离的实现。SFINAE留给需要精确控制重载决议的场景。掌握这些技巧后，你就能写出既类型安全又高度可扩展的通用组件。
