<p style=""><strong>1.什么是std::mutex</strong></p><p style="text-indent: 2em"><code>std::mutex</code> 是C++11引入的标准库头文件中定义的一个类，代表“互斥锁”(Mutual Exclusion)。用于保护共享数据免受多线程同时访问的主要<strong>同步原语</strong>。</p><p style="text-indent: 2em"><strong>核心思想：</strong>互斥锁就像一个小房间（临界区）的钥匙。一次只有一个线程可以持有这把钥匙(锁)。当线程持有钥匙时，它可以进入房间访问共享数据。其他线程必须等待，直到钥匙被放回(解锁)，然后它们才能竞争去拿到这把钥匙。</p><p style="text-indent: 2em"></p><p style=""><strong>2.为什么需要</strong><code>std::mutex</code><strong> ?</strong></p><p style="text-indent: 2em">在多线程环境中，如果多个线程不加控制地同时读写同一块共享数据，会导致数据竞争(Data Race)。数据竞争的后果是未定义行为(Undefined Behavior)，可能导致程序崩溃、计算错误、数据损坏等难以预料的后果。</p><p style="text-indent: 2em"><code>std::mutex</code> 的作用就是消除数据竞争，确保任何时候最多只有一个线程可以执行被保护的代码段(临界区),从而保证数据操作的原子性和正确性。</p><p style=""><strong>3.核心成员函数</strong></p><div style="overflow-x: auto; overflow-y: hidden;"><table style="width: 864px"><colgroup><col style="width: 100px"><col style="width: 764px"></colgroup><tbody><tr style="height: 60px;"><td colspan="1" rowspan="1" colwidth="100"><p style="">函数</p></td><td colspan="1" rowspan="1" colwidth="764"><p style="">说明</p></td></tr><tr style="height: 60px;"><th colspan="1" rowspan="1" colwidth="100"><p style=""><code>lock()</code></p></th><th colspan="1" rowspan="1" colwidth="764"><p style=""><strong>尝试获取锁</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。如果锁已被其他线程占用，则调用线程将被阻塞（进入睡眠状态），直到锁被释放。如果锁当前未被占用，则调用线程获得该锁。</span></p></th></tr><tr style="height: 60px;"><td colspan="1" rowspan="1" colwidth="100"><p style=""><code>unlock()</code></p></td><td colspan="1" rowspan="1" colwidth="764"><p style=""><strong>释放锁</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。将锁的状态设置为空闲，允许其他被阻塞的线程尝试获取它。</span></p></td></tr><tr style="height: 60px;"><td colspan="1" rowspan="1" colwidth="100"><p style=""><code>try_lock()</code></p></td><td colspan="1" rowspan="1" colwidth="764"><p style=""><strong>尝试非阻塞地获取锁</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。如果锁已被占用，函数立即返回 </span><code>false</code><span style="font-size: 15px; color: rgb(15, 17, 21)">，线程不会被阻塞。如果成功获取锁，则返回 </span><code>true</code><span style="font-size: 15px; color: rgb(15, 17, 21)">。</span></p></td></tr></tbody></table></div><p style=""><strong>重要特性</strong>：</p><ul><li><p style=""><code>std::mutex</code> 既不可复制也不可移动。</p></li><li><p style="">同一个线程不允许对已经锁定的 <code>std::mutex</code> 再次调用 <code>lock()</code> 或 <code>try_lock()</code>，这会导致<strong>未定义行为</strong>（通常是死锁）。这种锁称为<strong>非递归锁</strong>。</p></li></ul><p style="">4.基本使用方式及其风险</p><pre><code>#include &lt;iostream&gt;
#include &lt;thread&gt;
#include &lt;mutex&gt;

std::mutex g_mutex; // 全局互斥锁
int shared_data = 0; // 共享数据

void increment() {
    for (int i = 0; i &lt; 100000; ++i) {
        g_mutex.lock();    // 进入临界区前加锁
        ++shared_data;     // 临界区：操作共享数据
        g_mutex.unlock();  // 离开临界区后解锁
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout &lt;&lt; "Final value: " &lt;&lt; shared_data &lt;&lt; std::endl; // 总是 200000
    return 0;
}</code></pre><p style=""><strong>风险</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">：上述直接使用 </span><code>lock()</code><span style="font-size: 16px; color: rgb(15, 17, 21)"> 和 </span><code>unlock()</code><span style="font-size: 16px; color: rgb(15, 17, 21)"> 的方式是</span><strong>不安全</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">的。如果在临界区中发生了异常、或者程序员忘记调用 </span><code>unlock()</code><span style="font-size: 16px; color: rgb(15, 17, 21)">，锁将永远不会被释放，导致所有等待该锁的线程</span><strong>永久阻塞（死锁）</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">。</span></p><p style=""></p><p style=""><strong>5.更安全的方式：使用 RAII 管理锁</strong></p><p style="text-indent: 2em"><span style="font-size: 16px; color: rgb(15, 17, 21)">为了解决上述问题，C++ 标准库提供了</span><strong>RAII</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">（Resource Acquisition Is Initialization）风格的包装器类，来自动管理锁的生命周期。</span></p><p style="text-indent: 2em"><span style="font-size: 16px; color: rgb(15, 17, 21)"><strong>a.</strong></span><code>std::lock_guard</code></p><p style="text-indent: 2em"><code>std::lock_guard</code><span style="font-size: 16px; color: rgb(15, 17, 21)"> 是一个轻量级的 RAII 包装器。它在构造时自动锁定互斥量，在析构时（例如离开作用域时）自动解锁。即使中间发生异常，也能保证锁被释放。</span></p><p style="text-indent: 2em"><strong>适用场景</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">：简单的临界区，整个作用域都需要加锁。</span><strong>99% 的情况都应该优先使用它。</strong></p><pre><code>void safe_increment() {
    for (int i = 0; i &lt; 100000; ++i) {
        // 构造函数中调用 g_mutex.lock()
        std::lock_guard&lt;std::mutex&gt; lock(g_mutex);
        ++shared_data;
        // lock 的析构函数在作用域结束时自动调用 g_mutex.unlock()
    }
}</code></pre><p style="text-indent: 2em"><strong>b.</strong><code>std::unique_lock()</code></p><p style="text-indent: 2em"><code>std::unique_lock</code> 比 <code>std::lock_guard</code> 更灵活，但开销稍大。它提供了以下额外功能：</p><ul><li><p style=""><strong>延迟加锁</strong>：构造时可以指定 <code>std::defer_lock</code>，不立即加锁，之后再手动调用 <code>lock()</code>。</p></li><li><p style=""><strong>提前解锁</strong>：可以手动调用 <code>unlock()</code> 在作用域结束前释放锁，减少锁的持有时间。</p></li><li><p style=""><strong>所有权转移</strong>：<code>std::unique_lock</code> 是可移动的，但不可复制。</p></li><li><p style="">可以与条件变量 <code>std::condition_variable</code> 一起使用（这是必须的）。</p></li></ul><pre><code>void flexible_increment() {
    for (int i = 0; i &lt; 100000; ++i) {
        std::unique_lock&lt;std::mutex&gt; ulock(g_mutex, std::defer_lock);
        // ... 这里可以执行一些不需要锁的操作 ...
        ulock.lock(); // 现在需要操作共享数据了，手动加锁
        ++shared_data;
        ulock.unlock(); // 可以提前解锁
        // ... 这里又可以执行一些不需要锁的操作 ...
        // ulock 析构时，如果还持有锁，会自动解锁
    }
}</code></pre><p style="text-indent: 2em"></p><p style="text-indent: 2em"><strong>适用场景</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">：需要更灵活锁管理的复杂情况，或需要与条件变量配合时。</span></p><p style="text-indent: 2em"></p><p style=""><strong>6.其他类型的互斥量</strong></p><p style="text-indent: 2em">标准库还提供了其他几种互斥量以适应不同场景：</p><div style="overflow-x: auto;
