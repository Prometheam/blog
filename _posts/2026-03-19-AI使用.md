### Claude Code 学习记录
#### 1.Skills（技能）: 本质是把一组提示词封装成可复用的快捷操作。
##### 1.1Skill 怎么写
  在以下任一目录创建 .md 文件即可：
    - 项目级（仅当前项目可用）：.claude/commands/xxx.md
    - 用户级（全局可用）：~/.claude/commands/xxx.md
  文件名就是命令名。比如创建 debug.md，就可以用 /debug 调用。
  文件内容格式
    就是纯 Markdown，内容会作为 prompt 注入给 Claude：
  好的 skill 告诉 Claude 做什么、不做什么、输出什么样，而不是怎么做的每一步。

##### 1.2 实战栗子：一个实用的代码审查skill:
  ```
  # .claude/commands/review.md
  # review

  审查 $ARGUMENTS 中的变更。

  步骤：
  1. 读取 git diff 获取变更内容
  2. 逐文件检查：逻辑错误、边界情况、性能隐患
  3. 对每个问题给出严重程度(高/中/低)和修复代码

  规则：
  - 忽略风格问题（交给 linter）
  - 不改无关代码
  - 没问题就不输出
  ```

#### 2.Agents（子代理）
##### 2.1 Agent概念
从主对话中派生的独立执行单元，claude code内置的几种Subagent：

- Explore — 快速搜索和探索代码库
- Plan — 设计实现方案
- general-purpose — 通用多步骤任务
可以并行启动多个 agent 互不干扰，也可以在后台运行。

##### 2.2 用 Claude Agent SDK 开发自定义 Agent流程
简单说：增强你自己的开发流程用 Skill，构建给别人用的 AI 产品用 Agent SDK。
第一步：定义 Agent 的能力边界
  和设计 skill 一样，先想清楚三件事：

  - 它要做什么（审查代码、调试、部署…）
  - 它能做什么（能访问哪些工具和数据）
  - 它不该做什么（不该改的文件、不该执行的操作）

第二步：实现工具函数
  工具是 agent 的手脚，每个工具就是一个函数，Claude 通过函数签名和 docstring 来理解何时调用它：

```
 def read_file(path: str) -> str:
      """读取指定路径的文件内容"""
      with open(path) as f:
          return f.read()

  def get_git_diff(base_branch: str = "main") -> str:
      """获取当前分支与指定分支的代码差异"""
      import subprocess
      result = subprocess.run(
          ["git", "diff", base_branch],
          capture_output=True, text=True
      )
      return result.stdout

  def run_tests(test_path: str = "") -> str:
      """运行测试并返回结果"""
      import subprocess
      cmd = f"pytest {test_path}" if test_path else "pytest"
      result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
      return result.stdout + result.stderr
```
  工具设计要点：
  - 单一职责，一个函数做一件事
  - docstring 写清楚，这是 Claude 理解工具用途的唯一依据
  - 返回值精简，太长的输出浪费上下文窗口
  - 只暴露必要的工具，给多了 Claude 会乱用

  第三步：组装 Agent
  用 Anthropic 的 anthropic SDK，核心是 tool use 机制——一个循环：
  用户输入 → Claude 思考 → 调用工具 → 获取结果 → 继续思考 → 输出

  伪代码流程：
```
import anthropic

  client = anthropic.Anthropic()

  tools = [
      {
          "name": "read_file",
          "description": "读取指定路径的文件内容",
          "input_schema": {
              "type": "object",
              "properties": {
                  "path": {"type": "string", "description": "文件路径"}
              },
              "required": ["path"]
          }
      },
      {
          "name": "get_git_diff",
          "description": "获取当前分支与指定分支的代码差异",
          "input_schema": {
              "type": "object",
              "properties": {
                  "base_branch": {
                      "type": "string",
                      "description": "基准分支名",
                      "default": "main"
                  }
              }
          }
      },
  ]
```
  Agent 循环
  ```
  messages = [{"role": "user", "content": "审查当前分支的代码变更"}]
  while True:
      response = client.messages.create(
          model="claude-sonnet-4-20250514",
          system="你是代码审查助手。审查代码变更，关注逻辑错误、安全漏洞、性能问题。给出具体位置和修复建议。",
          messages=messages,
          tools=tools,
          max_tokens=4096,
      )

      # Claude 选择停止 → 输出最终结果
      if response.stop_reason == "end_turn":
          print(response.content[0].text)
          break

      # Claude 请求调用工具 → 执行并返回结果
      if response.stop_reason == "tool_use":
          for block in response.content:
              if block.type == "tool_use":
                  result = execute_tool(block.name, block.input)
                  messages.append({"role": "assistant", "content": response.content})
                  messages.append({
                      "role": "user",
                      "content": [{
                          "type": "tool_result",
                          "tool_use_id": block.id,
                          "content": result,
                      }]
                  })
  ```
  这就是 agent 的全部核心——一个 while 循环 + tool use API。所有 Agent SDK 都是对这个循环的封装。

  第四步：加防护
  裸 agent 不安全，必须加：
  - 工具执行白名单 — 只允许预定义的工具调用
  - 人工确认 — 危险操作（写文件、执行命令）前先问人
  - 最大迭代次数 — 防止无限循环
  - 输出过滤 — 防止泄露敏感信息

  第五步：测试和迭代
  - 用固定的输入跑 agent，检查它是否选对了工具、调用参数是否正确
  - 测边界情况：工具调用失败、输入为空、多轮对话
  - 根据实际表现调整 system prompt 和工具描述

  总结
  开发 agent 的本质就是：好的 prompt + 合适的工具 + agent 循环。流程是先定义能力边界，再实现工具，然后组装循环，最后加防护和测试。

##### 4.1 Claude Code 接入 MCP Server 有两种方式
 方式一：命令行添加
  stdio 类型（最常见，本地进程）
  claude mcp add <server-name> -- <command> [args...]
例子：添加文件系统 MCP
  claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /path/to/dir
  例子：添加 GitHub MCP
  claude mcp add github -- npx -y @modelcontextprotocol/server-github
例子：添加 PostgreSQL MCP
  claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres postgresql://localhost/mydb

  查看已配置的 server
  claude mcp list
   删除
  claude mcp remove <server-name>

  方式二：写配置文件

  在 .claude/settings.json 中手动添加：
  ```
  {
    "mcpServers": {
      "filesystem": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"],
        "env": {}
      },
      "github": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "env": {
          "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxx"
        }
      },
      "remote-api": {
        "type": "sse",
        "url": "https://example.com/mcp/sse"
      }
    }
  }
  ```

  配置文件有三个层级，优先级从高到低：
  - 项目级：.claude/settings.json（跟着项目走，可提交到 git）
  - 用户级：~/.claude/settings.json（全局生效）
  - 命令行指定：claude --mcp-config config.json（临时加载）

两种传输方式
  ```
  ┌───────┬──────────────────────────────────────┬───────────────────┐
  │ 类型  │               适用场景               │     配置字段      │
  ├───────┼──────────────────────────────────────┼───────────────────┤
  │ stdio │ 本地进程，Claude Code 启动子进程通信 │ command + args    │
  ├───────┼──────────────────────────────────────┼───────────────────┤
  │ SSE   │ 远程服务，通过 HTTP 通信             │ type: "sse" + url │
  └───────┴──────────────────────────────────────┴───────────────────┘
  ```

##### 4.2 MCP工作原理
MCP（Model Context Protocol）是 Anthropic 推出的开放协议，用于让 AI 应用与外部工具和数据源标准化交互。

  核心架构
  MCP 采用客户端-服务器模型：
  - MCP Host：发起连接的 AI 应用（如 Claude Code、Claude Desktop）
  - MCP Client：嵌入在 Host 中，负责与 Server 建立和维护连接
  - MCP Server：提供具体能力的独立进程，每个 Server 暴露一组工具或资源

  通信基于 JSON-RPC 2.0，传输层支持两种方式：
  - stdio：Server 作为子进程启动，通过标准输入/输出通信（Claude Code 默认方式）
  - SSE：Server 作为远程 HTTP 服务，通过 Server-Sent Events 通信

  Server 提供三类能力
  1. Tools（工具）— 可被 AI 调用的函数，如查询数据库、发请求、操作文件。这是最常用的能力。
  2. Resources（资源）— 可被读取的数据，如文件内容、数据库记录，由 AI 主动拉取。
  3. Prompts（提示模板）— 预定义的提示词模板，帮助用户快速完成特定任务。

  工作流程
  1. Host 启动时，根据配置创建 Client 并拉起对应的 Server 进程
  2. Client 与 Server 完成能力协商（initialize 握手），获知 Server 提供哪些 tools/resources/prompts
  3. AI 在对话中决定需要调用某个工具时，通过 Client 向 Server 发送 tools/call 请求
  4. Server 执行操作，返回结果给 Client，再交由 AI 继续推理
  5. 整个过程对用户透明，AI 自动决定何时调用哪个工具

  配置示例
  Claude Code 中在 .claude/settings.json 里配置 MCP Server：
  ```
  {
    "mcpServers": {
      "my-server": {
        "command": "node",
        "args": ["path/to/server.js"],
        "env": { "API_KEY": "xxx" }
      }
    }
  }
  ```
  关键设计思想
  - 解耦：Server 独立开发部署，Host 不需要知道具体实现
  - 标准化：所有 Server 遵循同一协议，一个 Server 可被任意 Host 使用
  - 安全：Server 运行在独立进程中，权限可隔离；工具调用需用户确认
  - 可组合：一个 Host 可同时连接多个 Server，组合不同能力
4.3 编写 MCP Server

  方式一：TypeScript SDK（官方推荐）
  1. 初始化项目

  ```
mkdir my-mcp-server && cd my-mcp-server
  npm init -y
  npm install @modelcontextprotocol/sdk

    2. 编写 Server

  import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
  import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
  import { z } from "zod";

  const server = new McpServer({
    name: "my-server",
    version: "1.0.0",
  });

  // 注册一个工具
  server.tool(
    "get_weather",                          // 工具名
    "获取指定城市的天气信息",                  // 描述（AI 靠这个决定是否调用）
    { city: z.string().describe("城市名") }, // 参数 schema
    async ({ city }) => {                    // 处理函数
      // 你的业务逻辑
      const temp = Math.floor(Math.random() * 30 + 5);
      return {
        content: [{ type: "text", text: `${city}当前温度 ${temp}°C` }],
      };
    }
  );

  // 启动
  const transport = new StdioServerTransport();
  await server.connect(transport);
  ```

 ```

  关键概念

  Tool 的返回格式固定为：

  ```
{
    content: [
      { type: "text", text: "文本内容" },
      { type: "image", data: "base64...", mimeType: "image/png" },
      { type: "resource", resource: { uri: "...", text: "..." } }
    ],
    isError?: boolean  // 标记是否为错误结果
  }

  参数校验用 Zod schema 定义，SDK 自动生成 JSON Schema 供 AI 参考：

  {
    city: z.string().describe("城市名"),
    days: z.number().min(1).max(7).describe("预报天数"),
    unit: z.enum(["celsius", "fahrenheit"]).optional().describe("温度单位")
  }

  除了 Tool，还可以注册 Resource 和 Prompt：

  // 资源：被动读取的数据
  server.resource("config", "config://app", async (uri) => ({
    contents: [{ uri: uri.href, text: JSON.stringify(appConfig) }]
  }));

  // 提示模板
  server.prompt("review", { code: z.string() }, async ({ code }) => ({
    messages: [{ role: "user", content: { type: "text", text: `请审查这段代码：\n${code}` } }]
  }));
  ```

#### 5.Hooks（钩子） 

在特定事件（工具调用前后）自动执行的 shell 命令，用于审核或拦截
● Claude Code Hooks 配置

  配置位置

  ~/.claude/settings.json（全局）或 项目/.claude/settings.json（项目级）

  支持的事件

```
  ┌──────────────┬───────────────────┐
  │     事件     │     触发时机      │
  ├──────────────┼───────────────────┤
  │ PreToolUse   │ 工具执行前        │
  ├──────────────┼───────────────────┤
  │ PostToolUse  │ 工具执行后        │
  ├──────────────┼───────────────────┤
  │ Notification │ Claude 发出通知时 │
  ├──────────────┼───────────────────┤
  │ Stop         │ Claude 完成响应时 │
  └──────────────┴───────────────────┘
```



  配置格式

 ```
 {
    "hooks": {
      "PreToolUse": [
        {
          "matcher": "Bash",
          "hooks": [
            {
              "type": "command",
              "command": "你的脚本或命令"
            }
          ]
        }
      ]
    }
  }
 ```

  - matcher：匹配的工具名，如 Bash、Write、Edit、Read 等，不填则匹配所有工具
  - type：目前只有 "command"
  - command：要执行的 shell 命令

  Hook 的输入输出

  输入：通过 stdin 传入 JSON，包含工具名和参数：

```
  {
    "tool_name": "Bash",
    "tool_input": {
      "command": "rm -rf /some/path"
    }
  }
```

  输出：
  - 退出码 0 → 允许继续
  - 退出码 2 → 阻止操作，stdout 内容作为拒绝理由显示
  - 退出码其他非0 → 阻止操作

  实际示例

  1. 阻止危险命令

 ```
 {
    "hooks": {
      "PreToolUse": [
        {
          "matcher": "Bash",
          "hooks": [
            {
              "type": "command",
              "command": "cat | python -c \"import sys,json; d=json.load(sys.stdin); cmd=d['tool_input']['command']; sys.exit(2 if 'rm -rf' in cmd else 0)\""
            }
          ]
        }
      ]
    }
  }
 ```



  2. 写文件后自动格式化

  ```
{
    "hooks": {
      "PostToolUse": [
        {
          "matcher": "Write",
          "hooks": [
            {
              "type": "command",
              "command": "npx prettier --write \"$FILEPATH\" 2>/dev/null"
            }
          ]
        }
      ]
    }
  }
  ```



  3. 所有工具调用时记录日志

  ```
{
    "hooks": {
      "PreToolUse": [
        {
          "hooks": [
            {
              "type": "command",
              "command": "echo '$(date) $TOOL_NAME' >> ~/.claude/tool-log.txt"
            }
          ]
        }
      ]
    }
  }
  ```



  注意没有 matcher 表示匹配所有工具。

  环境变量

  Hook 命令中可以使用这些环境变量：

  - $TOOL_NAME — 工具名
  - $FILEPATH — 涉及的文件路径（Write/Edit/Read 时可用）

快速添加

最快的方式是直接编辑 settings.json：全局` vim ~/.claude/settings.json`项目级`vim .claude/settings.json`  修改后立即生效，不需要重启 Claude Code。
