### 引言

文搜图（Text-to-Image Retrieval）是我们视频监控平台的核心功能之一——安保人员输入"红色上衣的男子"，系统从数百万帧画面中秒级检索出匹配结果。这背后是跨模态嵌入模型 + 向量检索引擎的协同工作。

这篇文章从项目实际出发，深入讲解文搜图的核心原理（对比学习、Dual Encoder架构）、系统架构设计、关键代码实现、以及在昇腾NPU上的性能优化经验。

---

### 1. 核心原理：跨模态对齐

#### 1.1 为什么文本能搜图

```
传统搜索：文本 → 关键词匹配 → 带标签的图片（依赖人工标注）

语义搜索：文本 → 向量 ─┐
                        ├─→ 向量空间中计算距离 → 最相似的图片
         图片 → 向量 ─┘

核心思想：
  将文本和图像编码到同一个向量空间
  语义相近的文本和图像在空间中距离接近

  "一只白色的猫" → [0.12, -0.34, 0.56, ...]  ← 文本向量
   白猫照片      → [0.11, -0.32, 0.58, ...]  ← 图像向量
   距离很近！ → 余弦相似度 > 0.85 → 匹配！
```

#### 1.2 对比学习（Contrastive Learning）

```
┌──────────────────────────────────────────────────────────────────┐
│               CLIP/GME 对比学习训练过程                            │
│                                                                  │
│  训练数据: N对 (图像, 文本) 配对                                  │
│                                                                  │
│  ┌───────────────┐         ┌───────────────┐                    │
│  │ 图像编码器     │         │ 文本编码器     │                    │
│  │ (ViT/ResNet)  │         │ (Transformer) │                    │
│  └───────┬───────┘         └───────┬───────┘                    │
│          │                          │                            │
│          ▼                          ▼                            │
│  I₁ I₂ I₃ ... Iₙ          T₁ T₂ T₃ ... Tₙ                    │
│                                                                  │
│  相似度矩阵 (N×N):                                               │
│       T₁    T₂    T₃   ... Tₙ                                  │
│  I₁ [0.95] 0.12  0.08  ... 0.03   ← 对角线最大（正样本对）     │
│  I₂  0.10 [0.92] 0.15  ... 0.07                                │
│  I₃  0.05  0.11 [0.88] ... 0.09                                │
│  ...                                                            │
│  Iₙ  0.02  0.06  0.04  ...[0.91]                               │
│                                                                  │
│  损失函数: InfoNCE Loss                                          │
│  最大化对角线（正对）相似度，最小化其余（负对）相似度             │
└──────────────────────────────────────────────────────────────────┘
```

#### 1.3 我们使用的模型：GME-Qwen2-VL-2B

```
模型解读：
  gme          — General Multimodal Embedding（智源BAAI发布）
  qwen2_vl     — 骨干网络：Qwen2-VL（通义千问2视觉语言模型）
  2b           — 约20亿参数
  .kllm        — 昇腾量化格式（类似GGUF/ONNX的昇腾专用格式）

架构：Dual Encoder（双编码器）
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  图像输入 → [Vision Encoder (ViT)] → 图像特征 → [Projection] → 512维向量
│                                                          │
│  文本输入 → [Text Encoder (Qwen2)] → 文本特征 → [Projection] → 512维向量
│                                                          │
│  两个编码器独立运行，可以预计算图像特征                    │
│  检索时只需实时计算文本向量 + 向量检索                     │
└──────────────────────────────────────────────────────────┘

vs 单编码器(如BLIP-2)：
  双编码器：图文分别编码，适合检索（图像可预计算）
  单编码器：图文联合编码，精度高但不适合大规模检索（每次都要重新编码）
```

│                                         │          QBIC向量底库  │      │
│                                         │          (ANN索引)     │      │

│                                                                         │
│ 链路2: 文搜图检索（用户请求触发）                                        │

│                                        │                                │

```

#### 2.2 VDS Pipeline集成

```
在我们的系统中，特征提取和QBIC检索通过VDS Pipeline串联：

Pipeline配置:
  CAlgorithmTsFeature (scene_mask=FEATURE)
    → 图像特征提取 → QBIC入库

  CAlgorithmTsInference (scene_mask=CUSTOM_1)
    → 文本特征提取 → QBIC比对 → 结果返回

QBIC句柄通过Rule注册到Pipeline中：
  Pipeline内部提取完特征后直接调用QBIC完成比对
  形成端到端的推理流程，减少数据拷贝
```

### 3. 关键实现

#### 3.1 图像特征提取（AscendCL推理）

```cpp
class ImageFeatureExtractor {
public:
    ImageFeatureExtractor(const std::string& model_path) {
        // 加载GME视觉编码器(.om格式)
        aclmdlLoadFromFile(model_path.c_str(), &model_id_);
        model_desc_ = aclmdlCreateDesc();
        aclmdlGetDesc(model_desc_, model_id_);
        prepareBuffers();
    }

    // 提取单帧图像的512维特征向量
    std::vector<float> extract(const uint8_t* yuv_data, int width, int height) {
        // 1. DVPP硬件预处理：YUV → RGB → Resize(224×224) → Normalize
        auto rgb_tensor = dvpp_.processImage(yuv_data, width, height,
                                              224, 224, stream_);

        // 2. 拷贝到模型输入buffer
        aclrtMemcpyAsync(input_buffer_, input_size_,
                         rgb_tensor, input_size_,
                         ACL_MEMCPY_DEVICE_TO_DEVICE, stream_);

        // 3. 执行推理
        aclmdlExecute(model_id_, input_dataset_, output_dataset_);

        // 4. 获取输出特征向量
        std::vector<float> feature(512);
        aclrtMemcpy(feature.data(), 512 * sizeof(float),
                    output_buffer_, 512 * sizeof(float),
                    ACL_MEMCPY_DEVICE_TO_HOST);

        // 5. L2归一化（余弦相似度 = 归一化后的内积）
        normalize(feature);
        return feature;
    }

private:
    void normalize(std::vector<float>& vec) {
        float norm = 0.0f;
        for (float v : vec) norm += v * v;
        norm = std::sqrt(norm);
        if (norm > 1e-6f) {
            for (float& v : vec) v /= norm;
        }
    }

    DvppProcessor dvpp_;
    uint32_t model_id_;
    aclmdlDesc* model_desc_;
    void* input_buffer_;
    void* output_buffer_;
    aclrtStream stream_;
    // ... dataset相关成员省略
};
```

#### 3.3 QBIC向量检索

```cpp
class QBICSearchEngine {
public:
    // 创建底库
    void createLibrary(const std::string& lib_name, int dim = 512) {
        qbic_create_library(lib_name.c_str(), dim, QBIC_METRIC_COSINE);
    }

    // 入库（批量插入特征）
    void insertFeatures(const std::string& lib_name,
                        const std::vector<std::vector<float>>& features,
                        const std::vector<int64_t>& ids) {
        for (size_t i = 0; i < features.size(); ++i) {
            qbic_insert_feature(lib_name.c_str(),
                               features[i].data(), 512, ids[i]);
        }
        // 触发索引重建（IVF或HNSW）
        qbic_build_index(lib_name.c_str());
    }

    // 检索Top-K
    struct SearchResult {
        int64_t frame_id;
        float similarity;
    };

    std::vector<SearchResult> search(const std::string& lib_name,
                                     const std::vector<float>& query_vec,
                                     int top_k = 10) {
        std::vector<int64_t> result_ids(top_k);
        std::vector<float> result_scores(top_k);

        int actual_k = qbic_feature_compare_sync(
            lib_name.c_str(),
            query_vec.data(), 512,
            top_k,
            result_ids.data(),
            result_scores.data());

        std::vector<SearchResult> results;
        for (int i = 0; i < actual_k; ++i) {
            results.push_back({result_ids[i], result_scores[i]});
        }
        return results;
    }
};
```

#### 3.4 自定义告警诊断（文本与当前帧匹配）

```cpp
// 场景：判断当前帧是否匹配某些告警文本描述
bool diagnoseAlert(const uint8_t* frame_data, int w, int h,
                   const std::vector<std::string>& alert_texts,
                   float threshold = 0.75f) {
    // 1. 提取当前帧图像特征
    auto img_feature = image_extractor_.extract(frame_data, w, h);

    // 2. 创建临时底库，插入当前帧
    std::string temp_lib = "temp_alert_" + generateUUID();
    qbic_.createLibrary(temp_lib);
    qbic_.insertFeatures(temp_lib, {img_feature}, {0});

    // 3. 逐条文本比对
    for (const auto& text : alert_texts) {
        auto text_feature = text_extractor_.extract(text);
        auto results = qbic_.search(temp_lib, text_feature, 1);

        if (!results.empty() && results[0].similarity > threshold) {
            // 匹配告警！
            qbic_.deleteLibrary(temp_lib);
            return true;
        }
    }

    qbic_.deleteLibrary(temp_lib);
    return false;
}
```

### 4. 向量检索原理

#### 4.1 相似度度量

```
余弦相似度（我们使用）：
  cos(A, B) = (A · B) / (||A|| × ||B||)
  范围: [-1, 1]，1表示完全相同
  
  如果向量已L2归一化（||A||=1, ||B||=1）：
  cos(A, B) = A · B（直接内积！）
  → 检索时只需计算内积，极快

为什么选余弦而不是L2距离：
  余弦关注方向（语义相似性），不关注长度
  "一只猫" 和 "一只漂亮的白色小猫" 方向相近但长度不同
  余弦相似度高，L2距离可能较大
```

#### 4.2 ANN索引加速

```
暴力检索（Brute Force）：
  100万张图 × 512维 × 4字节 = 2GB
  每次检索需要计算100万次内积 → ~10ms（CPU）
  可以接受？但如果是1亿张图呢？→ 1秒，不可接受

ANN（Approximate Nearest Neighbor）索引：

┌────────────────────────────────────────────────────────────┐
│           QBIC内部的索引策略                                 │
├────────────┬───────────┬───────────────────────────────────┤
│ 索引类型   │ 检索速度  │ 原理                              │
├────────────┼───────────┼───────────────────────────────────┤
│ IVF        │ 快        │ 聚类→只在最近的几个簇内搜索       │
│ HNSW       │ 极快      │ 多层跳表图，从粗到细层层逼近     │
│ PQ         │ 极快      │ 向量压缩（512维→32字节），省内存  │
│ IVF+PQ     │ 超快      │ 聚类+压缩，适合亿级数据          │
└────────────┴───────────┴───────────────────────────────────┘

我们的选择：
  < 100万帧：HNSW（召回率高，延迟<1ms）
  > 100万帧：IVF+PQ（内存可控，延迟~5ms，召回率>95%）
```

### 5. 性能优化

#### 5.1 DVPP硬件预处理

```
不优化：CPU解码YUV + Resize + Normalize → ~15ms/帧
优化后：DVPP硬件解码 + VPC Resize → ~0.5ms/帧（30倍提升）

DVPP Pipeline：
  YUV输入 → [DVPP VPC Resize 224×224] → [色域转换RGB] → NPU推理
  全程在设备端完成，零CPU参与
```

#### 5.2 批量特征提取

```cpp
// 单帧逐个推理：8ms × 1000帧 = 8秒（太慢）
// 批量推理（batch=16）：每批20ms × 63批 = 1.26秒（6倍提升）

std::vector<std::vector<float>> batchExtract(
    const std::vector<FrameData>& frames, int batch_size = 16) {
    
    std::vector<std::vector<float>> all_features;
    all_features.reserve(frames.size());

    for (size_t i = 0; i < frames.size(); i += batch_size) {
        int actual_batch = std::min(batch_size, (int)(frames.size() - i));
        
        // 批量预处理 + 推理
        auto batch_features = extractBatch(frames.data() + i, actual_batch);
        
        all_features.insert(all_features.end(),
                           batch_features.begin(), batch_features.end());
    }
    return all_features;
}
```

#### 5.3 特征缓存策略

```
问题：同一视频帧可能被多次查询触发特征提取
解决：特征入库时同时写入Redis缓存

入库流程优化：
  视频帧 → 计算frame_hash(MD5) → 查Redis
    ├── 命中 → 直接用缓存特征入QBIC
    └── 未命中 → NPU推理 → 写Redis(TTL=24h) → 入QBIC

Redis存储：
  Key: "feat:{camera_id}:{frame_hash}"
  Value: 512×4字节 = 2KB（二进制存储）
  命中率实测：~40%（相邻巡检帧变化不大时）
```

### 7. 总结

文搜图系统的核心技术栈：

| 层次 | 技术 | 作用 |
|------|------|------|
| 模型层 | GME-Qwen2-VL-2B | 跨模态对齐，生成统一语义向量 |
| 推理层 | AscendCL + DVPP | 硬件加速推理和预处理 |
| 检索层 | QBIC (HNSW/IVF) | 亿级向量毫秒级检索 |
| 存储层 | MySQL + Redis | 元数据持久化 + 特征缓存 |
| 调度层 | VDS Pipeline | 端到端推理流水线编排 |

**本质**：文搜图 = 对比学习训练的Dual Encoder + 高效ANN向量检索。理解了这两个核心，无论底层用CLIP、GME还是其他模型，无论检索引擎用QBIC、Milvus还是FAISS，架构思路都是一样的。
