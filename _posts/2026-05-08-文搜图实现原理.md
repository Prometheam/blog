文搜图功能实现概述:
	入库阶段(图像特征提取)：视频帧(YUV) → Qwen2-VL视觉编码器(gme_qwen2_vl_2b.kllm) → 图像特征向量 → QBIC底库存储 → 同时HEX编码写入DB持久化
	检索阶段(文本特征提取 + QBIC比对): 自然语言prompt → Qwen2-VL文本编码器(gme_qwen2_vl_2b.kllm) → 文本特征向量 → QBIC比对(通过 VDS Pipeline 将文本特征提取和 QBIC 比对串联成了端到端流程——QBIC 句柄通过 Rule 注册到 Pipeline
  中，Pipeline 内部提取完文本特征后直接调 QBIC 完成比对) → TopK结果
	自定义告警诊断:创建临时底库 → 插入当前帧图像特征 → 遍历告警文本 → 逐条提取文本特征 → QBIC 同步比对 → 判断是否超阈值。这里是显式地把"提取"和"比对"分开调用的。

核心原理：
	依赖多模态嵌入模型gme_qwen2_vl_2b.kllm，用于将图文映内容射到同一向量空间，典型的用途是文搜图、跨模态检索。

```
	- gme — General Multimodal Embedding，智源研究院(BAAI)发布的通用多模态嵌入模型
	- qwen2_vl — 基于 Qwen2-VL（通义千问2视觉语言模型）作为骨干网络
	- 2b — 约20亿参数规模
	- kllm — 模型文件格式后缀，可能是 KLLM 格式的量化/压缩模型文件
	```
	GME模型的关键能力是跨模态对齐 -- 同一语义的图像和文本在向量空间中距离接近。Qwen2-VL作为骨干网络提供双编码器：视觉编码器处理图像，文本编码器处理文本，两者通过对比学习对齐到同一向量空间。
	
	QBIC最初来源于20世纪90年代IBM公司的一项开创性的基于内容的图像检索技术，这也是后来的以图搜图、图像识别和多媒体数据检索的基础。核心思想：QBIC允许用户通过图像本身的视觉内容（如颜色、纹理、形状、布局等）来进行检索，而不依赖与标签。
	QBIC在当前体系里负责向量存储(底库管理)、索引构建和相似度检索，是特征比对的核心组件。
	
总结：文搜图的本质是将文本和图像映射到同一个语义空间，并在这个空间里计算它们的相似度
