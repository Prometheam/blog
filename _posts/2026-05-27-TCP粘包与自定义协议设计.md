### 引言

"TCP粘包"是网络编程面试的高频考点，也是实际开发中每个后端工程师都必须正确处理的问题。TCP是流式协议，它不保证"一次send对应一次recv"——你发的两条消息可能被合并成一次接收，也可能一条消息被拆成多次接收。

在我的项目中，几乎每个自定义协议都需要处理这个问题。今天系统性地讲清楚粘包的本质、解决方案，以及如何设计一个工业级的自定义二进制协议。

---

### 1. "粘包"的本质

#### 1.1 TCP是字节流，不是消息流

```
UDP: 消息边界保留
  send("Hello")  →  recv() = "Hello"      ← 一条一条，边界清晰
  send("World")  →  recv() = "World"

TCP: 字节流，无边界
  send("Hello")  ┐
  send("World")  ┘→ recv() = "HelloWorld"  ← "粘包"
  
  send("Hello World, this is a long message...")
      → recv() = "Hello Wor"              ← "拆包"（只收到一部分）
      → recv() = "ld, this is a long message..."
```

#### 1.2 为什么会粘包/拆包？

```
发送端原因：
  1. Nagle算法：小包合并后一次发送（减少网络小包）
  2. 发送缓冲区：多次write的数据在缓冲区中连续存放

接收端原因：
  3. 接收缓冲区：多次到达的数据在缓冲区中连续存放
  4. read读取量：一次read可能读到多条消息的数据

网络层原因：
  5. MSS分段：大消息被TCP层按MSS切分成多个段
  6. 中间路由：MTU限制可能进一步分片
```

#### 1.3 "粘包"这个词其实不准确

严格来说，TCP没有"包"的概念——它只有字节流。"粘包"只是应用层消息边界丢失的表现。正确的描述是：**应用层需要自行从TCP字节流中还原消息边界**。

### 2. 解决方案

#### 2.1 方案一：固定长度

```cpp
// 每条消息固定128字节
constexpr int MSG_SIZE = 128;

// 发送
void sendMsg(int fd, const char* msg) {
    char buf[MSG_SIZE] = {};
    strncpy(buf, msg, MSG_SIZE - 1);
    sendAll(fd, buf, MSG_SIZE);  // 必须发完整128字节
}

// 接收
void recvMsg(int fd, char* msg) {
    recvAll(fd, msg, MSG_SIZE);  // 必须收满128字节
}
```

**优点**：实现最简单
**缺点**：浪费带宽（短消息填充空字节），不灵活

#### 2.2 方案二：分隔符

```cpp
// 用 \r\n 作为消息分隔符（HTTP/Redis协议方式）
std::string readLine(int fd) {
    std::string line;
    char c;
    while (true) {
        ssize_t n = recv(fd, &c, 1, 0);
        if (n <= 0) break;
        if (c == '\n') {
            if (!line.empty() && line.back() == '\r')
                line.pop_back();
            return line;
        }
        line += c;
    }
    return line;
}
```

**优点**：文本协议友好（HTTP、Redis、SMTP）
**缺点**：逐字节扫描效率低，消息体不能包含分隔符（需要转义）

#### 2.3 方案三：长度前缀（Length-Prefixed）— 推荐

```
消息格式：
  ┌─────────────┬───────────────────────────┐
  │ Length (4B) │     Payload (N bytes)     │
  └─────────────┴───────────────────────────┘
  
  Length = Payload的字节数（不含Length本身）
```

这是最常用也是最推荐的方案——几乎所有二进制协议都用这种方式。

### 3. 完整实现：长度前缀编解码器

```cpp
#include <cstdint>
#include <cstring>
#include <string>
#include <vector>
#include <sys/socket.h>
#include <arpa/inet.h>
#include <unistd.h>

class Codec {
public:
    // 编码：添加4字节长度头
    static std::string encode(const std::string& message) {
        uint32_t len = htonl(static_cast<uint32_t>(message.size()));
        std::string packet(4 + message.size(), '\0');
        memcpy(&packet[0], &len, 4);
        memcpy(&packet[4], message.data(), message.size());
        return packet;
    }

    // 解码状态机：处理粘包/拆包
    // 返回解析出的完整消息列表（可能0条、1条或多条）
    std::vector<std::string> decode(const char* data, size_t len) {
        std::vector<std::string> messages;
        buffer_.append(data, len);

        while (true) {
            if (state_ == WAIT_HEADER) {
                if (buffer_.size() < 4) break;  // 头部不完整，等更多数据
                
                uint32_t net_len;
                memcpy(&net_len, buffer_.data(), 4);
                expected_len_ = ntohl(net_len);
                
                // 安全检查：防止恶意超大包
                if (expected_len_ > MAX_MESSAGE_SIZE) {
                    throw std::runtime_error("Message too large");
                }
                
                buffer_.erase(0, 4);
                state_ = WAIT_BODY;
            }

            if (state_ == WAIT_BODY) {
                if (buffer_.size() < expected_len_) break;  // 消息体不完整
                
                messages.push_back(buffer_.substr(0, expected_len_));
                buffer_.erase(0, expected_len_);
                state_ = WAIT_HEADER;
            }
        }

        return messages;
    }

private:
    enum State { WAIT_HEADER, WAIT_BODY };
    static constexpr size_t MAX_MESSAGE_SIZE = 16 * 1024 * 1024;  // 16MB上限
    
    State state_ = WAIT_HEADER;
    uint32_t expected_len_ = 0;
    std::string buffer_;  // 接收缓冲区（跨多次recv积累）
};
```

使用示例：
```cpp
// 发送端
std::string msg1 = Codec::encode("Hello");
std::string msg2 = Codec::encode("World");
send(fd, (msg1 + msg2).data(), msg1.size() + msg2.size(), 0);
// 两条消息可能被合并发送——没关系

// 接收端
Codec codec;
char buf[4096];
ssize_t n = recv(fd, buf, sizeof(buf), 0);
// 一次recv可能收到半条、一条或多条消息——都能正确处理
auto messages = codec.decode(buf, n);
for (const auto& msg : messages) {
    printf("Got message: %s\n", msg.c_str());
}
```

### 4. TLV协议格式（Type-Length-Value）

比纯长度前缀更灵活，支持多种消息类型和可选字段：

```
TLV格式：
  ┌──────────┬──────────┬───────────────────────┐
  │ Type(2B) │ Length(4B)│    Value (N bytes)    │
  └──────────┴──────────┴───────────────────────┘

示例协议：
  Type=0x0001: 登录请求
  Type=0x0002: 登录响应
  Type=0x0003: 心跳
  Type=0x0004: 消息
```

```cpp
#pragma pack(push, 1)
struct TLVHeader {
    uint16_t type;    // 消息类型
    uint32_t length;  // Value部分长度
};
#pragma pack(pop)

class TLVCodec {
public:
    struct Message {
        uint16_t type;
        std::string payload;
    };

    std::vector<Message> decode(const char* data, size_t len) {
        std::vector<Message> messages;
        buffer_.append(data, len);

        while (buffer_.size() >= sizeof(TLVHeader)) {
            TLVHeader header;
            memcpy(&header, buffer_.data(), sizeof(TLVHeader));
            header.type = ntohs(header.type);
            header.length = ntohl(header.length);

            if (header.length > MAX_PAYLOAD) {
                throw std::runtime_error("Payload too large");
            }

            size_t total_size = sizeof(TLVHeader) + header.length;
            if (buffer_.size() < total_size) break;  // 不完整

            Message msg;
            msg.type = header.type;
            msg.payload = buffer_.substr(sizeof(TLVHeader), header.length);
            messages.push_back(std::move(msg));
            buffer_.erase(0, total_size);
        }

        return messages;
    }

    static std::string encode(uint16_t type, const std::string& payload) {
        TLVHeader header;
        header.type = htons(type);
        header.length = htonl(static_cast<uint32_t>(payload.size()));

        std::string packet(sizeof(TLVHeader) + payload.size(), '\0');
        memcpy(&packet[0], &header, sizeof(TLVHeader));
        memcpy(&packet[sizeof(TLVHeader)], payload.data(), payload.size());
        return packet;
    }

private:
    static constexpr size_t MAX_PAYLOAD = 16 * 1024 * 1024;
    std::string buffer_;
};
```

### 5. 完整协议设计示例

一个生产级的自定义协议通常包含：

```
┌───────────────────────────────────────────────────────────┐
│                     协议报文格式                           │
├──────┬──────┬──────┬──────┬──────┬─────────┬─────────────┤
│Magic │ Ver  │ Type │SeqNo │Length│ Header  │    Body     │
│ (2B) │ (1B) │ (1B) │ (4B) │ (4B)│Extension│  (Payload)  │
│0xCAFE│      │      │      │      │ (变长)  │             │
└──────┴──────┴──────┴──────┴──────┴─────────┴─────────────┘

Magic:  魔数，用于快速校验（抵御端口扫描等垃圾数据）
Ver:    协议版本号（支持协议升级）
Type:   消息类型（请求/响应/心跳/通知...）
SeqNo:  序列号（请求-响应配对、去重）
Length: Body长度
Header Extension: 可选的扩展头（如认证token、trace id）
Body:   业务数据（通常用Protobuf序列化）
```

```cpp
#pragma pack(push, 1)
struct ProtocolHeader {
    uint16_t magic;       // 0xCAFE
    uint8_t  version;     // 协议版本
    uint8_t  msg_type;    // 消息类型
    uint32_t sequence;    // 序列号
    uint32_t body_length; // Body长度
    uint16_t header_ext_length; // 扩展头长度
    uint16_t checksum;    // 头部校验和
};
#pragma pack(pop)

static_assert(sizeof(ProtocolHeader) == 16);  // 确保紧凑布局
```

### 6. 工程实践中的坑

#### 6.1 必须处理short write/short read

```cpp
// ❌ 错误：假设一次write就能发完
write(fd, data, len);

// ✅ 正确：循环发送直到完毕
ssize_t sendAll(int fd, const void* data, size_t len) {
    const char* ptr = static_cast<const char*>(data);
    size_t remaining = len;
    while (remaining > 0) {
        ssize_t n = send(fd, ptr, remaining, 0);
        if (n < 0) {
            if (errno == EINTR) continue;
            if (errno == EAGAIN) { /* 注册EPOLLOUT等待 */ }
            return -1;
        }
        ptr += n;
        remaining -= n;
    }
    return len;
}
```

#### 6.2 字节序（大端/小端）

```cpp
// 网络字节序是大端（Big Endian）
// x86是小端（Little Endian）
// 必须转换！

uint32_t hostToNet(uint32_t host) { return htonl(host); }
uint32_t netToHost(uint32_t net)  { return ntohl(net); }
uint16_t hostToNet(uint16_t host) { return htons(host); }
uint16_t netToHost(uint16_t net)  { return ntohs(net); }
```

#### 6.3 Nagle算法与延迟

如果你的协议是请求-响应式，Nagle算法会等到ACK返回才发数据（延迟40ms）：

```cpp
// 关闭Nagle算法（低延迟场景必须关）
int flag = 1;
setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &flag, sizeof(flag));
```

#### 6.4 防止恶意大包OOM

```cpp
// 必须限制最大消息长度！
if (header.length > MAX_MESSAGE_SIZE) {
    // 恶意客户端发了一个声称4GB的包
    // 如果不检查就分配4GB内存 → OOM
    closeConnection(fd, "message too large");
    return;
}
```

### 总结

处理TCP粘包的本质是**在字节流上重建消息边界**。三种方案中：

- **固定长度**：最简单但浪费，适合定长命令
- **分隔符**：适合文本协议，但需转义且扫描慢
- **长度前缀**：最通用最推荐，生产环境的标准做法

设计自定义协议时记住：
1. 加魔数（Magic）防垃圾数据
2. 加版本号支持协议演进
3. 加序列号支持请求-响应配对
4. **一定要限制最大包长度**
5. 用状态机解码，优雅处理半包
