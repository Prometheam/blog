### 引言

epoll是Linux平台上IO多路复用的终极形态，也是几乎所有高性能网络框架（Nginx、Redis、Netty、muduo）的核心引擎。从select的O(n)遍历到epoll的O(1)就绪通知，这不只是一个API的升级，而是**设计哲学的根本转变**。

在工作中，我维护过单机承载50万+长连接的IM网关，其内核就是基于epoll + Reactor的架构。今天从内核实现的角度来深度复盘epoll。

---

### 1. epoll 的设计哲学

#### 1.1 核心思想：从"你问我"到"我告诉你"

```
select/poll 模型（主动询问）：
  用户：这1万个fd里有哪些就绪了？
  内核：等我一个个检查... fd[0]没有、fd[1]没有... fd[9876]有！fd[9999]有！
  代价：O(n)，每次都全量检查

epoll 模型（事件驱动）：
  用户：帮我监听这1万个fd
  内核：好的（注册回调）
  ...（某fd就绪时）...
  内核：fd[9876]和fd[9999]就绪了，直接拿走
  代价：O(k)，k = 就绪fd数量，与总量无关
```

#### 1.2 内核数据结构

epoll在内核中维护两个核心数据结构：

```
epoll 内核结构：

  ┌─────────────────────────────────────────────────┐
  │              eventpoll 结构体                    │
  │                                                 │
  │  ┌─────────────────────┐   ┌───────────────┐   │
  │  │   红黑树 (rbr)       │   │ 就绪链表      │   │
  │  │  所有注册的fd        │   │ (rdllist)     │   │
  │  │                     │   │               │   │
  │  │      [fd=100]       │   │ → [fd=9876]   │   │
  │  │     /       \       │   │ → [fd=9999]   │   │
  │  │  [fd=50]  [fd=200]  │   │               │   │
  │  │  /   \    /   \     │   │  仅存放就绪fd │   │
  │  │ ...  ... ...  ...   │   │  O(1)获取     │   │
  │  │                     │   │               │   │
  │  │ 增删改查：O(log n)  │   │               │   │
  │  └─────────────────────┘   └───────────────┘   │
  │                                                 │
  │  等待队列 (wq)：阻塞在epoll_wait的进程         │
  └─────────────────────────────────────────────────┘
```

- **红黑树**：管理所有注册的fd，增删改查都是O(log n)
- **就绪链表**：存储已就绪的fd，epoll_wait只需取走链表内容
- **回调机制**：当fd状态变化时，内核通过回调函数将其加入就绪链表

### 2. 三个核心API

```cpp
#include <sys/epoll.h>

// 1. 创建epoll实例（返回epoll文件描述符）
int epoll_create(int size);      // size已被忽略，>0即可
int epoll_create1(int flags);    // 推荐，flags可设EPOLL_CLOEXEC

// 2. 注册/修改/删除监听事件
int epoll_ctl(int epfd,          // epoll文件描述符
              int op,            // 操作类型
              int fd,            // 目标fd
              struct epoll_event *event); // 事件配置

// 3. 等待事件就绪
int epoll_wait(int epfd,
               struct epoll_event *events,  // 输出数组：内核填入就绪事件
               int maxevents,               // 数组大小
               int timeout);                // 超时ms，-1永久阻塞
```

#### epoll_ctl 操作类型

```cpp
EPOLL_CTL_ADD  // 注册新fd到红黑树
EPOLL_CTL_MOD  // 修改已注册fd的监听事件
EPOLL_CTL_DEL  // 从红黑树删除fd
```

#### epoll_event 结构

```cpp
struct epoll_event {
    uint32_t events;    // 事件掩码
    epoll_data_t data;  // 用户数据（通常存fd或指针）
};

typedef union epoll_data {
    void    *ptr;   // 存自定义结构体指针（推荐）
    int      fd;    // 存文件描述符
    uint32_t u32;
    uint64_t u64;
} epoll_data_t;
```

**工程经验**：生产代码中推荐用`data.ptr`存储自定义的连接对象指针，而不是`data.fd`。这样事件触发时可以直接拿到连接上下文，避免再用fd去map中查找。

#### 常用事件掩码

```
┌──────────────┬────────────────────────────────────────────┐
│    事件      │              含义                          │
├──────────────┼────────────────────────────────────────────┤
│ EPOLLIN      │ 可读（包括对端正常关闭）                  │
│ EPOLLOUT     │ 可写（发送缓冲区有空间）                  │
│ EPOLLERR     │ 错误（自动监听，不需要手动设置）          │
│ EPOLLHUP     │ 挂断（自动监听）                          │
│ EPOLLRDHUP   │ 对端关闭连接或关闭写端（Linux 2.6.17+）  │
│ EPOLLET      │ 边缘触发模式（Edge Triggered）            │
│ EPOLLONESHOT │ 一次性触发，触发后需重新注册              │
└──────────────┴────────────────────────────────────────────┘
```

### 3. LT 与 ET 模式：深入理解

这是epoll最容易踩坑的地方。

#### 3.1 水平触发（LT, Level Triggered）— 默认模式

```
原理：只要fd的缓冲区有数据，每次epoll_wait都会通知你

时间线：
  t1: 对端发送 5KB 数据
  t2: epoll_wait 返回 EPOLLIN  ← 通知
  t3: 你 read(fd, buf, 2048) 读了 2KB
  t4: epoll_wait 返回 EPOLLIN  ← 再次通知（还有3KB没读完）
  t5: 你 read(fd, buf, 4096) 读完剩余
  t6: epoll_wait 阻塞          ← 缓冲区空了，不再通知
```

**特点**：宽容，不会丢数据。没读完下次还会提醒你。

#### 3.2 边缘触发（ET, Edge Triggered）

```
原理：只在fd状态变化时通知一次（从无数据→有数据）

时间线：
  t1: 对端发送 5KB 数据
  t2: epoll_wait 返回 EPOLLIN  ← 通知一次
  t3: 你 read(fd, buf, 2048) 读了 2KB
  t4: epoll_wait 阻塞！        ← 不再通知！还有3KB没读！
  ...直到对端再发新数据触发新的"边缘"...
```

**ET模式的铁律**：每次收到事件，必须循环读/写直到返回EAGAIN！

```cpp
// ET模式下正确的读取方式
void handleReadET(int fd) {
    while (true) {
        char buf[4096];
        ssize_t n = read(fd, buf, sizeof(buf));
        if (n < 0) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                break;  // 读完了，正常退出
            }
            // 真正的错误
            perror("read");
            break;
        }
        if (n == 0) {
            // 对端关闭
            break;
        }
        // 处理读到的数据...
    }
}
```

#### 3.3 如何选择？

```
LT模式：
  ✅ 编程简单，不容易丢数据
  ✅ 读写不需要循环到EAGAIN
  ❌ 可能产生忙轮询（如果可写事件不及时取消）
  📎 适合：业务逻辑复杂、对性能要求不极端的场景

ET模式：
  ✅ 减少epoll_wait返回次数，减少系统调用
  ✅ 天然避免忙轮询
  ❌ 编程复杂，必须一次处理完
  ❌ 必须配合非阻塞fd使用
  📎 适合：高性能服务器、连接数多但活跃度低的场景
```

**工程经验**：Nginx用的是ET模式，Redis用的是LT模式。在我的项目中，IM长连接网关用ET（连接多但大部分时间空闲），RPC框架用LT（编码简单，请求密集时差距不大）。

### 4. 完整C++实现：高性能Echo Server

```cpp
#include <sys/socket.h>
#include <sys/epoll.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <unistd.h>
#include <fcntl.h>
#include <cstring>
#include <cstdio>
#include <cerrno>

constexpr int MAX_EVENTS = 1024;
constexpr int BUFFER_SIZE = 4096;

class EpollServer {
public:
    EpollServer(int port, bool use_et = true)
        : port_(port), listen_fd_(-1), epoll_fd_(-1), use_et_(use_et) {}

    ~EpollServer() {
        if (epoll_fd_ >= 0) close(epoll_fd_);
        if (listen_fd_ >= 0) close(listen_fd_);
    }

    bool start() {
        // 创建监听socket
        listen_fd_ = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0);
        if (listen_fd_ < 0) {
            perror("socket");
            return false;
        }

        int opt = 1;
        setsockopt(listen_fd_, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
        setsockopt(listen_fd_, SOL_SOCKET, SO_REUSEPORT, &opt, sizeof(opt));

        struct sockaddr_in addr{};
        addr.sin_family = AF_INET;
        addr.sin_addr.s_addr = INADDR_ANY;
        addr.sin_port = htons(port_);

        if (bind(listen_fd_, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
            perror("bind");
            return false;
        }

        // backlog设大一些，防止SYN洪泛时连接队列溢出
        if (listen(listen_fd_, 4096) < 0) {
            perror("listen");
            return false;
        }

        // 创建epoll实例
        epoll_fd_ = epoll_create1(EPOLL_CLOEXEC);
        if (epoll_fd_ < 0) {
            perror("epoll_create1");
            return false;
        }

        // 注册监听socket（监听socket一般用LT，避免丢连接）
        struct epoll_event ev{};
        ev.events = EPOLLIN;  // 监听socket用LT
        ev.data.fd = listen_fd_;
        if (epoll_ctl(epoll_fd_, EPOLL_CTL_ADD, listen_fd_, &ev) < 0) {
            perror("epoll_ctl");
            return false;
        }

        printf("[EpollServer] Listening on port %d (%s mode)\n",
               port_, use_et_ ? "ET" : "LT");
        return true;
    }

    void run() {
        struct epoll_event events[MAX_EVENTS];

        while (true) {
            int nready = epoll_wait(epoll_fd_, events, MAX_EVENTS, -1);

            if (nready < 0) {
                if (errno == EINTR) continue;
                perror("epoll_wait");
                break;
            }

            for (int i = 0; i < nready; ++i) {
                int fd = events[i].data.fd;
                uint32_t ev = events[i].events;

                if (fd == listen_fd_) {
                    handleAccept();
                } else if (ev & (EPOLLERR | EPOLLHUP)) {
                    // 对端异常关闭
                    printf("[EpollServer] fd=%d error/hangup\n", fd);
                    close(fd); // close会自动从epoll中删除
                } else if (ev & EPOLLIN) {
                    handleRead(fd);
                }
            }
        }
    }

private:
    void setNonBlocking(int fd) {
        int flags = fcntl(fd, F_GETFL, 0);
        fcntl(fd, F_SETFL, flags | O_NONBLOCK);
    }

    void handleAccept() {
        // 循环accept（ET模式下或多个连接同时到达）
        while (true) {
            struct sockaddr_in client_addr{};
            socklen_t addr_len = sizeof(client_addr);
            int client_fd = accept4(listen_fd_,
                                     (struct sockaddr*)&client_addr,
                                     &addr_len,
                                     SOCK_NONBLOCK | SOCK_CLOEXEC);

            if (client_fd < 0) {
                if (errno == EAGAIN || errno == EWOULDBLOCK) {
                    break; // 所有连接都已accept
                }
                perror("accept4");
                break;
            }

            // 注册到epoll
            struct epoll_event ev{};
            ev.events = EPOLLIN | EPOLLRDHUP;
            if (use_et_) ev.events |= EPOLLET;
            ev.data.fd = client_fd;

            if (epoll_ctl(epoll_fd_, EPOLL_CTL_ADD, client_fd, &ev) < 0) {
                perror("epoll_ctl ADD");
                close(client_fd);
                continue;
            }

            printf("[EpollServer] New client fd=%d from %s:%d\n",
                   client_fd, inet_ntoa(client_addr.sin_addr),
                   ntohs(client_addr.sin_port));
        }
    }

    void handleRead(int fd) {
        char buf[BUFFER_SIZE];

        while (true) {
            ssize_t n = read(fd, buf, sizeof(buf));

            if (n < 0) {
                if (errno == EAGAIN || errno == EWOULDBLOCK) {
                    break; // 数据读完（ET模式必须读到这里）
                }
                perror("read");
                close(fd);
                return;
            }

            if (n == 0) {
                // 对端正常关闭
                printf("[EpollServer] fd=%d closed by peer\n", fd);
                close(fd);
                return;
            }

            // Echo: 写回数据
            ssize_t written = 0;
            while (written < n) {
                ssize_t w = write(fd, buf + written, n - written);
                if (w < 0) {
                    if (errno == EAGAIN) {
                        // 发送缓冲区满，生产环境应注册EPOLLOUT事件
                        break;
                    }
                    perror("write");
                    close(fd);
                    return;
                }
                written += w;
            }

            // LT模式只读一次就够了（下次epoll_wait还会通知）
            if (!use_et_) break;
        }
    }

    int port_;
    int listen_fd_;
    int epoll_fd_;
    bool use_et_;
};

int main(int argc, char* argv[]) {
    bool use_et = true;
    if (argc > 1 && strcmp(argv[1], "--lt") == 0) {
        use_et = false;
    }

    EpollServer server(8080, use_et);
    if (server.start()) {
        server.run();
    }
    return 0;
}
```

### 5. epoll 的内核实现原理

#### 5.1 事件注册（epoll_ctl ADD）

```
1. 在红黑树中插入新节点（O(log n)）
2. 为该fd注册一个回调函数（ep_poll_callback）
3. 回调函数的作用：当fd状态变化时，将其加入就绪链表
```

#### 5.2 事件就绪（回调触发）

```
网卡收到数据 → 中断 → 协议栈处理 → 数据放入socket接收缓冲区
                                    ↓
                          执行 ep_poll_callback()
                                    ↓
                          将该fd的epitem加入就绪链表(rdllist)
                                    ↓
                          唤醒阻塞在epoll_wait的进程
```

#### 5.3 获取就绪事件（epoll_wait）

```
1. 检查就绪链表是否为空
2. 为空则阻塞（加入等待队列）
3. 被唤醒后，将就绪链表中的事件拷贝到用户空间数组
4. LT模式：如果fd仍就绪，重新加入就绪链表
   ET模式：不重新加入，等待下次状态变化
```

### 6. 生产环境最佳实践

#### 6.1 epoll 惊群问题

多线程/多进程同时epoll_wait同一个epoll fd时，一个连接到达会唤醒所有线程：

```cpp
// 解决方案1：EPOLLEXCLUSIVE（Linux 4.5+）
ev.events = EPOLLIN | EPOLLEXCLUSIVE;

// 解决方案2：SO_REUSEPORT（Linux 3.9+）
// 每个线程有独立的listen socket和epoll fd
int opt = 1;
setsockopt(fd, SOL_SOCKET, SO_REUSEPORT, &opt, sizeof(opt));
```

#### 6.2 EPOLLONESHOT 避免多线程竞争

多线程Reactor中，同一个fd的事件可能被分发给不同线程：

```cpp
// 注册时设置ONESHOT
ev.events = EPOLLIN | EPOLLET | EPOLLONESHOT;

// 处理完后重新注册（在处理线程中）
ev.events = EPOLLIN | EPOLLET | EPOLLONESHOT;
epoll_ctl(epfd, EPOLL_CTL_MOD, fd, &ev);
```

#### 6.3 正确处理EPOLLOUT

不要一开始就注册EPOLLOUT，否则会不停触发（发送缓冲区通常有空间）：

```cpp
// 正确做法：只在write返回EAGAIN时注册EPOLLOUT
ssize_t n = write(fd, data, len);
if (n < 0 && errno == EAGAIN) {
    // 缓冲区满，注册可写事件
    ev.events = EPOLLIN | EPOLLOUT | EPOLLET;
    epoll_ctl(epfd, EPOLL_CTL_MOD, fd, &ev);
    // 把未发完的数据存入发送缓冲区
}

// 可写事件触发后，发完数据就取消EPOLLOUT
void handleWrite(int fd) {
    // 发送缓冲数据...
    if (send_buffer_empty()) {
        ev.events = EPOLLIN | EPOLLET; // 去掉EPOLLOUT
        epoll_ctl(epfd, EPOLL_CTL_MOD, fd, &ev);
    }
}
```

### 7. 性能对比数据

基于wrk压测，100字节Echo，4核8G Linux服务器：

```
                连接数
         100     1,000    10,000   100,000
select  52K QPS   N/A      N/A       N/A
poll    54K QPS  29K QPS   6.2K     N/A
epoll   55K QPS  53K QPS  51K QPS  48K QPS
```

关键结论：
- **连接少时三者差距不大**（内核遍历开销被IO本身掩盖）
- **epoll性能与总连接数几乎无关**（只与活跃连接数相关）
- **poll/select随连接数线性下降**

### 8. 常见踩坑

1. **close(fd)后不需要epoll_ctl DEL**：关闭fd时内核会自动清理epoll中的注册
2. **fd复用导致的幽灵事件**：close后立即新建socket可能复用同一fd号，旧事件会误触发新连接
3. **ET模式下accept要循环**：多个连接同时到达只通知一次，必须accept到EAGAIN
4. **大文件传输用splice/sendfile**：不要read到用户态再write回去，零拷贝是王道

---

### 总结

epoll通过**红黑树+就绪链表+回调机制**三驾马车，实现了与总连接数无关的O(1)事件通知，是Linux高性能网络编程的基石。理解了select→poll→epoll的演进逻辑，你就能清晰地理解为什么现代服务器框架都以epoll为核心来设计Reactor模型。

在性能之外，更重要的是理解其背后的**设计思想**：把频繁变化的部分（事件注册）和高频操作（事件获取）分离，用空间换时间，用注册回调替代主动轮询。这种思想在软件设计中处处可见。
