<p style="">事件驱动是基本概念，这里不做赘述，参见上篇文章 <a href="http://124.220.188.239/console/posts/editor?name=61436c98-fef1-498a-9a14-e920f175343b" target="_blank" rel="">事件驱动架构</a>。</p><h4 style="" id="%E4%B8%80%E3%80%81actor%E6%A8%A1%E5%9E%8B">一、Actor模型</h4><h5 style="" id="actor-%E7%9A%84%E6%A0%B8%E5%BF%83%E7%BB%93%E6%9E%84%E5%92%8C%E5%B7%A5%E4%BD%9C%E6%B5%81">Actor 的核心结构和工作流</h5><p style="text-indent: 2em"><span style="font-size: 16px; color: rgb(15, 17, 21)">Actor 模型是一种用于处理高并发计算的</span><strong>编程模型</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">。它的核心思想是：</span><strong>万物皆 Actor</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">，每个 Actor 之间通过</span><strong>异步消息</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">进行通信，每个 Actor 独立处理自己的状态，没有共享内存。</span></p><p style="text-indent: 2em"><img src="/upload/image-NDJH.png" width="100%" height="100%" style="display: inline-block"></p><p style=""><strong>图解说明：</strong></p><ol><li><p style=""><strong>邮箱</strong>：每个 Actor 都有一个专属的<strong>消息队列（邮箱）</strong>。其他 Actor 发送的消息会先在此排队，等待被处理。这保证了消息的<strong>异步</strong>和<strong>有序</strong>传递。</p></li><li><p style=""><strong>行为逻辑</strong>：这是 Actor 的“大脑”。它从邮箱中<strong>一次取出一个消息</strong>进行处理。这种单线程处理方式天然避免了锁的竞争。</p></li><li><p style=""><strong>本地状态</strong>：Actor 可以拥有自己的私有数据（状态）。<strong>只有它自己能修改其状态</strong>，外部只能通过发送消息来请求其改变。这是实现“<strong>状态隔离</strong>”和“<strong>无共享</strong>”的关键。</p></li><li><p style=""><strong>处理消息后，Actor 可以做出三种响应</strong>：</p><ul><li><p style=""><strong>发送消息</strong>：给其他 Actor（如 <code>ActorB</code>）或自己发送新消息。</p></li><li><p style=""><strong>创建新 Actor</strong>：动态创建更多的 Actor 来分担工作。</p></li><li><p style=""><strong>改变自身行为</strong>：为处理下一条消息准备不同的逻辑（成为有限状态机）。</p></li></ul></li></ol><h5 style="" id="actor%E6%A8%A1%E5%9E%8B%E5%92%8C%E4%BC%A0%E7%BB%9F%E7%BA%BF%E7%A8%8B%E6%A8%A1%E5%9E%8B%E5%AF%B9%E6%AF%94">Actor模型和传统线程模型对比</h5><p style="text-indent: 2em">1. Actor模型</p><p style="margin-left: 24px!important; text-indent: 2em"><strong>状态存储：私有状态</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。每个 Actor 独占自己的数据，</span><strong>绝不共享</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>通信方式：</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">通过</span><strong>异步消息</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">进行显式通信，发送即忘，无需等待。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>并发问题：</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">天然规避了锁和死锁问题，因为状态内部是串行修改的。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>扩展性：高度可扩展</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。Actor 是轻量级实体（非线程），可以创建数百万个，并可在集群中透明分布。</span></p><p style="text-indent: 2em"><img src="/upload/image-EIQx.png" width="50%" height="auto" style="display: inline-block"> 2. 传统线程模型</p><p style="margin-left: 24px!important; text-indent: 2em"><strong>状态存储：共享内存</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">。多个线程可访问和修改同一数据。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>通信方式：</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">通过</span><strong>共享变量</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">进行隐式通信，需要复杂的同步机制（锁、信号量）。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>并发问题：</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">极易产生</span><strong>竞态条件</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">、</span><strong>死锁</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">等问题，调试困难。</span></p><p style="margin-left: 24px!important; text-indent: 2em"><strong>扩展性：</strong><span style="font-size: 15px; color: rgb(15, 17, 21)">受限于共享资源的竞争，扩展性有瓶颈。</span></p><p style="text-indent: 2em"><img src="/upload/image-fFVl.png" width="50%" height="auto" style="display: inline-block"></p><p style="text-indent: 2em"></p><p style="text-indent: 2em">总结：<span style="font-size: 16px; color: rgb(15, 17, 21)">Actor 模型通过</span><strong>消息传递</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">和</span><strong>状态隔离</strong><span style="font-size: 16px; color: rgb(15, 17, 21)">，将复杂的并发问题分解为简单的、独立运行的组件，从而优雅地解决了传统并发编程中的诸多难题</span></p><h4 style="" id="%E4%BA%8C%E3%80%81reactor%E6%A8%A1%E5%BC%8F">二、Reactor模式</h4><p style="text-indent: 2em">Reactor模式的核心是事件驱动，它通过一个或多个线程来监听和分发事件，然后将事件处理交给相应的处理器。根据Reactor的数量和线程池的使用情况，可以分为以下三种模型：单Reactor单线程模型、单Reactor多线程模型、主从Reactor多线程模型</p><h5 style="" id="2.1%E4%BA%8B%E4%BB%B6%E9%A9%B1%E5%8A%A8%E6%A8%A1%E5%BC%8F%E5%AF%B9%E6%AF%94">2.1事件驱动模式对比</h5><p style="text-indent: 2em">传统阻塞I/O模型<span style="font-size: 16px; color: rgb(15, 17, 21)"> (每个连接一个线程)</span></p><p style="text-indent: 2em"><span style="font-size: 16px; color: rgb(15, 17, 21)"><img src="/upload/image-JZZx.png" width="50%" height="auto" style="display: inline-block"></span></p><p style="text-indent: 2em">Reactor事件驱动模型<span style="font-size: 16px; color: rgb(15, 17, 21)"> (少量线程处理大量连接)</span></p><p style="text-indent: 2em"><img src="/upload/image-ICLv.png" width="50%" height="auto" style="display: inline-block"></p><h5 style="" id="2.2-%E6%A0%B8%E5%BF%83%E7%BB%84%E4%BB%B6%E5%85%B3%E7%B3%BB%E5%9B%BE">2.2 核心组件关系图</h5><p style="text-indent: 2em"><img src="/upload/image-wtMk.png" width="50%" height="auto" style="display: inline-block"></p><h5 style="" id="2.3-%E4%BA%8B%E4%BB%B6%E5%BE%AA%E7%8E%AF%E6%B5%81%E7%A8%8B">2.3 事件循环流程</h5><p style="text-indent: 2em"><img src="/upload/image-DARx.png" width="50%" height="auto" style="display: inline-block"></p><h5 style="" id="2.4-reactor%E4%B8%89%E7%A7%8D%E6%A8%A1%E5%9E%8B">2.4 Reactor三种模型</h5><p style=""><strong>图例说明</strong></p><ol><li><p style=""><strong>Reactor</strong>：事件分发中心，负责监听和分发事件。</p></li><li><p style=""><strong>Event Demultiplexer</strong>：同步事件分离器，底层使用I/O多路复用技术（如select、poll、epoll、kqueue）等待事件发生。</p></li><li><p style=""><strong>Event Dispatcher</strong>：事件分发器，将就绪的事件分发给对应的事件处理器。</p></li><li><p style=""><strong>Acceptor</strong>：处理连接事件，接受新连接并创建对应的Handler，注册到Reactor（或SubReactor）中。</p></li><li><p style=""><strong>Handler</strong>：处理非连接事件，如读、写事件。通常将耗时的业务处理交给线程池。</p></li><li><p style=""><strong>Worker Thread Pool</strong>：工作线程池，处理业务逻辑，避免阻塞Reactor线程。</p></li></ol><h6 style="" id="2.4.1%E5%8D%95reactor%E5%8D%95%E7%BA%BF%E7%A8%8B%E6%A8%A1%E5%9E%8B">2.4.1单Reactor单线程模型</h6><p style="text-indent: 2em"><span style="font-size: 14px;
