### 引言

在昇腾上部署模型时，大多数标准算子（Conv2D、MatMul、ReLU等）CANN已经提供了高度优化的实现。但总有些场景需要自定义算子——比如我们做视频质量评估时用到了一个非标准的注意力机制，CANN没有对应的融合算子，逐个调用小算子的性能损失达40%。

这时候就需要**Ascend C**——华为提供的C/C++风格算子开发语言，让你能直接编程AI Core的三个计算单元。相比之前的TBE（基于Python DSL），Ascend C对C++程序员更友好，思维模式也更直观。

### 1. Ascend C编程模型

#### 1.1 与CUDA Kernel的对比

```
CUDA编程模型（SIMT）：
  - 启动成千上万个线程
  - 每个线程执行相同的kernel代码
  - 线程通过threadIdx/blockIdx区分自己处理哪部分数据
  - 内存访问通过硬件Cache自动管理

Ascend C编程模型（SPMD + 显式流水）：
  - 将数据切分为多个块（Tiling），每个AI Core处理一块
  - 每个AI Core内部：显式编排Cube/Vector/Scalar三个流水线
  - 数据搬运必须手动编排（MTE引擎）
  - 三条流水线可以并行执行（计算和搬运重叠）

┌────────────────────────────────────────────────────────────────────┐
│         CUDA vs Ascend C 编程范式对比                                │
├─────────────────────┬─────────────────────┬────────────────────────┤
│ 维度                │ CUDA                │ Ascend C               │
├─────────────────────┼─────────────────────┼────────────────────────┤
│ 并行粒度            │ Thread (细粒度)     │ AI Core (粗粒度)       │
│ 数据搬运            │ 隐式 (Cache)        │ 显式 (DataCopy API)    │
│ 内存管理            │ 硬件Cache           │ 手动管理L1/L2 Buffer   │
│ 计算单元            │ CUDA Core (统一)    │ Cube/Vector/Scalar     │
│ 向量化              │ Warp (32线程)       │ Vector Unit (显式)     │
│ 同步                │ __syncthreads       │ pipe_barrier           │
│ 调试                │ cuda-gdb/nsight     │ Ascend Insight         │
└─────────────────────┴─────────────────────┴────────────────────────┘
```

### 2. Tiling策略

#### 2.1 为什么要Tiling

AI Core的L1 Buffer只有1MB——绝大多数Tensor远大于此。必须将数据切分为小块，逐块搬入L1计算：

```
原始Tensor: [1024, 4096] float16 = 8MB >> L1容量(1MB)

Tiling策略：切分为多块，每块能装进L1

方案1: 按行切分
  [1024, 4096] → 128个 [8, 4096] 的小块
  每块大小: 8 × 4096 × 2B = 64KB ← 能装进L1

方案2: 按块切分
  [1024, 4096] → [32, 32] 个 [32, 128] 的小块  
  每块大小: 32 × 128 × 2B = 8KB ← 更小，利于流水编排

┌────────────────────────────────────────────────┐
│             Tiling可视化                        │
│                                                │
│  ┌─────┬─────┬─────┬─────┐                    │
│  │Tile0│Tile1│Tile2│ ... │  ← 逐块搬入L1      │
│  ├─────┼─────┼─────┼─────┤     计算           │
│  │Tile4│Tile5│Tile6│ ... │     搬出结果        │
│  ├─────┼─────┼─────┼─────┤                    │
│  │ ... │ ... │ ... │ ... │                    │
│  └─────┴─────┴─────┴─────┘                    │
│                                                │
│  AI Core 0处理 Tile0, Tile4, Tile8, ...        │
│  AI Core 1处理 Tile1, Tile5, Tile9, ...        │
│  → 多核并行，每核逐块串行                      │
└────────────────────────────────────────────────┘
```

#### 2.2 Tiling参数计算

```cpp
// Host侧：计算Tiling参数，传递给Device侧Kernel
struct TilingData {
    uint32_t total_length;     // 数据总长度
    uint32_t tile_length;      // 每块长度
    uint32_t tile_num;         // 总块数
    uint32_t core_num;         // 使用的AI Core数
    uint32_t tiles_per_core;   // 每个core处理的块数
};

void computeTiling(TilingData& tiling, uint32_t data_length, uint32_t core_num) {
    // L1 Buffer可用空间（需预留给input和output两份）
    constexpr uint32_t L1_SIZE = 1024 * 1024;  // 1MB
    constexpr uint32_t BUFFER_NUM = 2;  // Double Buffer
    uint32_t max_tile_bytes = L1_SIZE / BUFFER_NUM;

    // 对齐要求：Vector Unit要求32字节对齐
    constexpr uint32_t ALIGN = 32;
    uint32_t max_tile_elements = (max_tile_bytes / sizeof(half)) & ~(ALIGN - 1);

    tiling.total_length = data_length;
    tiling.tile_length = std::min(max_tile_elements, data_length);
    tiling.tile_num = (data_length + tiling.tile_length - 1) / tiling.tile_length;
    tiling.core_num = std::min(core_num, tiling.tile_num);
    tiling.tiles_per_core = (tiling.tile_num + tiling.core_num - 1) / tiling.core_num;
}
```

### 3. 实战：实现自定义GELU算子

#### 3.1 GELU数学公式

```
GELU(x) = x × Φ(x) = x × 0.5 × (1 + erf(x/√2))

近似公式（tanh版本，更易于硬件实现）：
GELU(x) ≈ 0.5 × x × (1 + tanh(√(2/π) × (x + 0.044715 × x³)))
```

#### 3.2 Ascend C Kernel实现

```cpp
#include "kernel_operator.h"

using namespace AscendC;

class KernelGelu {
public:
    __aicore__ inline KernelGelu() {}

    __aicore__ inline void Init(GM_ADDR x, GM_ADDR y, uint32_t totalLength,
                                 uint32_t tileLength) {
        // 初始化Global Memory地址
        xGm_.SetGlobalBuffer((__gm__ half*)x, totalLength);
        yGm_.SetGlobalBuffer((__gm__ half*)y, totalLength);

        // 申请Local Buffer（L1片上内存）
        pipe_.InitBuffer(inQueueX_, 2, tileLength * sizeof(half));   // Double Buffer
        pipe_.InitBuffer(outQueueY_, 2, tileLength * sizeof(half));
        pipe_.InitBuffer(tmpBuf1_, 1, tileLength * sizeof(half));
        pipe_.InitBuffer(tmpBuf2_, 1, tileLength * sizeof(half));

        totalLength_ = totalLength;
        tileLength_ = tileLength;
    }

    __aicore__ inline void Process() {
        // 计算本AI Core负责的数据范围
        uint32_t coreId = GetBlockIdx();
        uint32_t coreNum = GetBlockNum();
        uint32_t tilesPerCore = (totalLength_ / tileLength_ + coreNum - 1) / coreNum;

        uint32_t startTile = coreId * tilesPerCore;
        uint32_t endTile = std::min(startTile + tilesPerCore,
                                     totalLength_ / tileLength_);

        for (uint32_t i = startTile; i < endTile; ++i) {
            CopyIn(i);     // Stage 1: 搬入
            Compute(i);    // Stage 2: 计算
            CopyOut(i);    // Stage 3: 搬出
        }
    }

private:
    // Stage 1: Global Memory → L1 Buffer
    __aicore__ inline void CopyIn(uint32_t tileIdx) {
        LocalTensor<half> xLocal = inQueueX_.AllocTensor<half>();

        // 从GM搬运一个tile到Local Buffer
        DataCopy(xLocal, xGm_[tileIdx * tileLength_], tileLength_);

        inQueueX_.EnQue(xLocal);  // 入队，通知计算阶段可以开始
    }

    // Stage 2: 在L1 Buffer上计算GELU
    __aicore__ inline void Compute(uint32_t tileIdx) {
        LocalTensor<half> xLocal = inQueueX_.DeQue<half>();  // 等待搬入完成
        LocalTensor<half> yLocal = outQueueY_.AllocTensor<half>();
        LocalTensor<half> tmp1 = tmpBuf1_.Get<half>();
        LocalTensor<half> tmp2 = tmpBuf2_.Get<half>();

        // GELU近似: 0.5 * x * (1 + tanh(sqrt(2/pi) * (x + 0.044715 * x^3)))
        half sqrt_2_over_pi = static_cast<half>(0.7978845608f);
        half coeff = static_cast<half>(0.044715f);
        half half_val = static_cast<half>(0.5f);
        half one = static_cast<half>(1.0f);

        // tmp1 = x^3
        Mul(tmp1, xLocal, xLocal, tileLength_);      // x^2
        Mul(tmp1, tmp1, xLocal, tileLength_);        // x^3

        // tmp1 = 0.044715 * x^3
        Muls(tmp1, tmp1, coeff, tileLength_);

        // tmp1 = x + 0.044715 * x^3
        Add(tmp1, xLocal, tmp1, tileLength_);

        // tmp1 = sqrt(2/pi) * (x + 0.044715 * x^3)
        Muls(tmp1, tmp1, sqrt_2_over_pi, tileLength_);

        // tmp1 = tanh(...)
        Tanh(tmp1, tmp1, tileLength_);

        // tmp1 = 1 + tanh(...)
        Adds(tmp1, tmp1, one, tileLength_);

        // tmp1 = 0.5 * (1 + tanh(...))
        Muls(tmp1, tmp1, half_val, tileLength_);

        // y = x * tmp1
        Mul(yLocal, xLocal, tmp1, tileLength_);

        outQueueY_.EnQue(yLocal);  // 通知搬出阶段
        inQueueX_.FreeTensor(xLocal);
    }

    // Stage 3: L1 Buffer → Global Memory
    __aicore__ inline void CopyOut(uint32_t tileIdx) {
        LocalTensor<half> yLocal = outQueueY_.DeQue<half>();  // 等待计算完成

        DataCopy(yGm_[tileIdx * tileLength_], yLocal, tileLength_);

        outQueueY_.FreeTensor(yLocal);
    }

    // 成员变量
    GlobalTensor<half> xGm_, yGm_;
    TPipe pipe_;
    TQue<QuePosition::VECIN, 2> inQueueX_;    // 输入队列(depth=2 for double buffer)
    TQue<QuePosition::VECOUT, 2> outQueueY_;  // 输出队列
    TBuf<QuePosition::VECCALC> tmpBuf1_, tmpBuf2_;  // 临时buffer
    uint32_t totalLength_;
    uint32_t tileLength_;
};

// Kernel入口函数
extern "C" __global__ __aicore__ void gelu_kernel(GM_ADDR x, GM_ADDR y,
                                                   GM_ADDR tiling_data) {
    // 从tiling_data中读取参数
    TilingData* tiling = (TilingData*)tiling_data;

    KernelGelu op;
    op.Init(x, y, tiling->total_length, tiling->tile_length);
    op.Process();
}
```

### 4. Double Buffer流水编排

#### 4.1 为什么要Double Buffer

```
单Buffer（串行执行）：
  搬入Tile0 → 计算Tile0 → 搬出Tile0 → 搬入Tile1 → 计算Tile1 → ...
  
  时间: ████████░░░░░░░░████████░░░░░░░░
        搬入    计算    搬出    搬入    计算
  
  MTE和计算单元不能重叠 → 利用率低

Double Buffer（流水并行）：
  Buffer A: 搬入Tile0 → 计算Tile0 → 搬出Tile0 → 搬入Tile2 → ...
  Buffer B:           → 搬入Tile1 → 计算Tile1 → 搬出Tile1 → ...

  时间: ████████████████████████████████
        搬入A  计算A  搬出A  搬入A
              搬入B  计算B  搬出B  
        
  搬运和计算重叠执行 → 利用率翻倍！
```

#### 4.2 流水线同步

```cpp
// Ascend C中Queue机制自动实现流水编排

// TQue<QuePosition::VECIN, 2> 中的 "2" 就是Double Buffer的depth

// 工作原理：
// EnQue(): 标记一个buffer已准备好（生产者完成）
// DeQue(): 等待一个buffer准备好后取出（消费者等待）

// CopyIn中: inQueueX_.EnQue(xLocal)  → 告诉计算阶段"数据搬好了"
// Compute中: inQueueX_.DeQue()         → 等待"数据搬好了"的信号

// 这本质上是一个生产者-消费者模式：
// CopyIn是Producer，Compute是Consumer
// Queue深度=2意味着CopyIn可以超前Compute一个Tile（Double Buffer）
```

### 5. 算子注册与调用

#### 5.1 Host侧算子注册

```cpp
// gelu_op.cpp (Host侧)
#include "acl/acl.h"
#include "acl/acl_op_compiler.h"

// 注册自定义算子
class GeluOp {
public:
    static aclError launch(aclrtStream stream,
                           void* x_dev, void* y_dev,
                           uint32_t length) {
        // 1. 计算Tiling
        TilingData tiling;
        computeTiling(tiling, length, 32);  // 使用32个AI Core

        // 2. 申请Tiling参数的设备内存
        void* tiling_dev = nullptr;
        aclrtMalloc(&tiling_dev, sizeof(TilingData), ACL_MEM_MALLOC_HUGE_FIRST);
        aclrtMemcpy(tiling_dev, sizeof(TilingData),
                    &tiling, sizeof(TilingData), ACL_MEMCPY_HOST_TO_DEVICE);

        // 3. 配置Kernel启动参数
        uint32_t blockDim = tiling.core_num;  // 启用的AI Core数

        // 4. 启动Kernel
        aclError ret = ACLRT_LAUNCH_KERNEL(gelu_kernel)(
            blockDim, stream,
            x_dev, y_dev, tiling_dev);

        aclrtFree(tiling_dev);
        return ret;
    }
};
```

### 6. 性能优化技巧

#### 6.1 计算与搬运重叠

```
优化前（串行）：
  时间轴: |--搬入--|--计算--|--搬出--|--搬入--|--计算--|--搬出--|
  MTE:    ████████                    ████████
  Vector:          ████████                    ████████
  总耗时: 6个阶段

优化后（Triple Buffer + 3级流水）：
  时间轴: |--T1--|--T2--|--T3--|--T4--|--T5--|
  MTE-in: █Tile0█ Tile1█ Tile2█ Tile3█
  Vector:        █Tile0█ Tile1█ Tile2█ Tile3█
  MTE-out:              █Tile0█ Tile1█ Tile2█
  
  搬入Tile(n+1) 与 计算Tile(n) 与 搬出Tile(n-1) 同时执行
  总耗时: 接近单阶段耗时 × (tile数+2)
  理想加速: 3x（三阶段完全重叠）
```

#### 6.2 向量化对齐

```cpp
// Vector Unit要求数据32字节对齐
// 如果数据长度不是32B的倍数，需要补齐

// 计算对齐后的长度
uint32_t alignUp(uint32_t length, uint32_t align) {
    return (length + align - 1) & ~(align - 1);
}

// 使用时：
uint32_t aligned_length = alignUp(actual_length, 16);  // 16个half = 32B
// 多余的元素在计算后需要mask掉或忽略
```

#### 6.3 Cube Unit矩阵运算

```cpp
// 当算子包含矩阵乘法时，应使用Cube Unit

// Cube Unit的约束：
// - 输入矩阵必须是 [M, K] × [K, N] 形式
// - M, K, N必须是16的倍数（AI Core的矩阵乘法粒度是16×16）
// - 数据格式要求：左矩阵NZ格式（fractal_z），右矩阵ND格式

// 使用Matmul高级API（自动处理格式转换和分块）

LocalTensor<half> matB = ...;  // [K, N]
LocalTensor<float> matC = ...; // [M, N] 结果用float避免精度损失

Matmul(matC, matA, matB, M, K, N);  // Cube Unit自动执行

问题：Vector利用率低 (<30%)
原因：数据搬运(MTE)成为瓶颈

问题：Pipeline Stall高 (>20%)
原因：流水线依赖导致等待
修复：调整计算顺序 / 增加中间buffer / 拆分依赖链

问题：L1 Buffer不够用
原因：Tile太大或临时变量过多
修复：减小Tile / 复用Buffer / 分段计算
```

### 8. 总结

```
┌─────────────────────────────────────────────────────────────────────┐
│              Ascend C算子开发要点                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. 思维转换：从CUDA的"写一个线程的逻辑"                           │
│     → 到Ascend C的"编排数据搬运+计算流水线"                        │
│                                                                     │
│  2. Tiling是核心：数据切分策略决定了L1利用率和并行度               │
│     → Tile太大：L1放不下                                           │
│     → Tile太小：搬运开销占比过高                                   │
│     → 最佳：计算时间 ≈ 搬运时间（完美流水重叠）                   │
│                                                                     │
│  3. Double/Triple Buffer是标配：                                    │
│     → 搬入下一块的同时计算当前块                                   │
│     → Queue机制自动处理同步                                        │
│                                                                     │
│  4. 对齐要求严格：                                                  │
│     → Vector: 32字节对齐                                           │
│     → Cube: M/K/N需为16倍数                                       │
│     → 数据格式: 某些算子要求特定layout(NZ, 5HD)                    │
│                                                                     │
│  5. 优化优先级：                                                    │
│     → 先确保正确性（用小Tile逐步验证）                             │
│     → 再优化搬运（Double Buffer, 预取）                            │
│     → 最后极致优化（指令级流水编排）                               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

对于大多数推理部署场景，你不需要写Ascend C算子——CANN内置算子库已经覆盖了95%的需求。但当你遇到自定义激活函数、非标准注意力机制、或者需要多个小算子融合时，Ascend C是提升性能的利器。掌握了Tiling + 流水编排的思想，即使不写算子，也能更好地理解ATC优化器的行为，做出更好的模型设计决策。
