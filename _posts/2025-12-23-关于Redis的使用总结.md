<p style="">不知不觉已经工作8年，我将以8年经验的C++程序员视角 ，从系统性、深度和与C++实践结合的角度来讲解Redis，用于技术复盘。以下内容将涵盖：</p><ol><li><p style="">Redis核心概念与数据类型</p></li><li><p style="">Redis与C++的交互（客户端选择与使用）</p></li><li><p style="">Redis在C++项目中的典型应用场景</p></li><li><p style="">Redis性能优化与注意事项</p></li><li><p style="">Redis持久化、高可用与集群</p></li><li><p style="">Redis6/7的新特性（如果适用）</p></li></ol><p style="">由于Redis内容广泛，这里将提炼关键点，并结合C++开发者的视角进行讲解。</p><p style=""></p><h2 style="" id="1.-redis%E6%A0%B8%E5%BF%83%E6%A6%82%E5%BF%B5%E4%B8%8E%E6%95%B0%E6%8D%AE%E7%B1%BB%E5%9E%8B">1. Redis核心概念与数据类型</h2><p style="">Redis是一个开源的内存数据结构存储，用作数据库、缓存和消息中间件。它支持多种数据结构，包括：</p><ul><li><p style="">字符串（String）</p></li><li><p style="">列表（List）</p></li><li><p style="">集合（Set）</p></li><li><p style="">有序集合（Sorted Set）</p></li><li><p style="">哈希（Hash）</p></li><li><p style="">位图（Bitmap）</p></li><li><p style="">流（Stream，用于消息队列）</p></li></ul><p style="">对于C++程序员，理解这些数据结构在Redis内部是如何实现的，有助于合理使用。</p><p style=""><span style="font-size: 14px; color: rgb(97, 102, 107)">例如，Redis的字符串是动态字符串（SDS），类似于C++的vector&lt;char&gt;，可以高效地追加和截断。</span><br><span style="font-size: 14px; color: rgb(97, 102, 107)">列表在早期版本是双向链表，但后来引入了ziplist（压缩列表）和quicklist（3.2版本后）来节省内存。</span><br><span style="font-size: 14px; color: rgb(97, 102, 107)">哈希和有序集合在元素较少时使用压缩列表，元素多时使用哈希表和跳表。</span></p><p style=""><span style="font-size: 14px; color: rgb(97, 102, 107)">这些实现细节对于选择数据类型和优化内存使用很重要。</span></p><p style=""></p><h2 style="" id="2.-redis%E4%B8%8Ec%2B%2B%E7%9A%84%E4%BA%A4%E4%BA%92">2. Redis与C++的交互</h2><p style="">C++与Redis交互通常通过客户端库。常用的有：</p><ul><li><p style="">hiredis（官方C客户端，简单，但需要自己封装）</p></li><li><p style="">redis-plus-plus（C++17客户端，推荐，封装良好）</p></li><li><p style="">其他如cpp_redis等</p></li></ul><p style="">以redis-plus-plus为例，示例代码：</p><pre><code>#include &lt;sw/redis++/redis++.h&gt;
#include &lt;iostream&gt;

int main() {
    try {
        // 创建Redis对象，连接到Redis服务器
        auto redis = sw::redis::Redis("tcp://127.0.0.1:6379");

        // 设置键值对
        redis.set("key", "val");

        // 获取键值
        auto val = redis.get("key");
        if (val) {
            std::cout &lt;&lt; *val &lt;&lt; std::endl;
        }

        // 使用哈希表
        redis.hset("hash", "field", "value");
        auto field_val = redis.hget("hash", "field");
        if (field_val) {
            std::cout &lt;&lt; *field_val &lt;&lt; std::endl;
        }
    } catch (const std::exception &amp;e) {
        std::cerr &lt;&lt; e.what() &lt;&lt; std::endl;
    }
}</code></pre><p style=""><span style="font-size: 14px; color: rgb(97, 102, 107)">注意：使用客户端库时，要处理网络异常和重连。生产环境可能需要连接池和哨兵支持。</span></p><h2 style="" id="3.-redis%E5%9C%A8c%2B%2B%E9%A1%B9%E7%9B%AE%E4%B8%AD%E7%9A%84%E5%85%B8%E5%9E%8B%E5%BA%94%E7%94%A8%E5%9C%BA%E6%99%AF">3. Redis在C++项目中的典型应用场景</h2><h3 style="" id="%E7%BC%93%E5%AD%98">缓存</h3><p style="">最常见的用途，缓存数据库查询结果。注意缓存穿透、击穿、雪崩问题。</p><ul><li><p style="">穿透：查询不存在的数据，导致每次都要查数据库。解决方案：布隆过滤器或缓存空值。</p></li><li><p style="">击穿：热点key过期，大量请求打到数据库。解决方案：互斥锁（使用Redis的SETNX实现）或永不过期（但需要异步更新）。</p></li><li><p style="">雪崩：大量key同时过期。解决方案：设置不同的过期时间。</p></li></ul><h3 style="" id="%E4%BC%9A%E8%AF%9D%E5%AD%98%E5%82%A8%EF%BC%88session-storage%EF%BC%89">会话存储（Session Storage）</h3><p style="">将用户会话存储在Redis中，实现无状态服务。注意设置合理的过期时间。</p><h3 style="" id="%E5%88%86%E5%B8%83%E5%BC%8F%E9%94%81">分布式锁</h3><p style="">使用Redis实现分布式锁，注意Redlock算法，但红锁存在争议，可根据场景选择。常用命令：SET key value NX PX 3000（设置过期时间，单位毫秒）。</p><h3 style="" id="%E6%B6%88%E6%81%AF%E9%98%9F%E5%88%97">消息队列</h3><p style="">使用列表的阻塞操作（BLPOP/BRPOP）实现简单的消息队列。更复杂的消息队列可使用Stream（Redis5.0引入）。</p><h3 style="" id="%E6%8E%92%E8%A1%8C%E6%A6%9C">排行榜</h3><p style="">使用有序集合（ZSET）可以方便地实现排行榜。</p><h3 style="" id="%E9%99%90%E6%B5%81">限流</h3><p style="">使用滑动窗口计数，例如使用字符串的INCR和EXPIRE，或使用Lua脚本保证原子性。</p><h2 style="" id="4.-redis%E6%80%A7%E8%83%BD%E4%BC%98%E5%8C%96%E4%B8%8E%E6%B3%A8%E6%84%8F%E4%BA%8B%E9%A1%B9">4. Redis性能优化与注意事项</h2><ul><li><p style="">内存优化：使用适当的数据结构，例如，小数据量时使用哈希表可能比字符串更节省内存（因为Redis为每个键分配一个对象，哈希表可以存储多个字段）。</p></li><li><p style="">批量操作：使用管道（pipeline）或批量命令（如MSET、HMGET）减少网络往返。</p></li><li><p style="">避免大键：单个键存储过大的数据（如几百MB的字符串）会导致操作延迟高，并可能阻塞Redis。</p></li><li><p style="">使用Lua脚本：将多个操作组合成一个原子操作，减少网络开销并保证原子性。</p></li><li><p style="">键名设计：不要太长，但也要可读。可以使用冒号分隔的命名空间，如"user:1000:profile"。</p></li></ul><h2 style="" id="5.-redis%E6%8C%81%E4%B9%85%E5%8C%96%E3%80%81%E9%AB%98%E5%8F%AF%E7%94%A8%E4%B8%8E%E9%9B%86%E7%BE%A4">5. Redis持久化、高可用与集群</h2><h3 style="" id="%E6%8C%81%E4%B9%85%E5%8C%96">持久化</h3><ul><li><p style="">RDB：快照，适用于备份和灾难恢复。但可能会丢失最后一次快照后的数据。</p></li><li><p style="">AOF：追加写操作日志，可以配置为每秒同步，最多丢失一秒的数据。AOF重写可以压缩文件。</p></li></ul><p style="">通常可以同时开启，在重启时优先使用AOF恢复。</p><h3 style="" id="%E9%AB%98%E5%8F%AF%E7%94%A8">高可用</h3><ul><li><p style="">主从复制：主节点写，从节点读。从节点可以再连接从节点，形成链式复制。</p></li><li><p style="">哨兵（Sentinel）：监控主节点，自动故障转移。客户端通过哨兵获取当前主节点地址。</p></li><li><p style="">集群（Cluster）：分布式数据分片，每个节点负责一部分槽（slot）。客户端需要支持集群协议（如redis-plus-plus）。</p></li></ul><p style=""></p><h2 style="" id="6.-redis6%2F7%E7%9A%84%E6%96%B0%E7%89%B9%E6%80%A7">6. Redis6/7的新特性</h2><ul><li><p style="">Redis6：多线程I/O（但命令执行仍是单线程），SSL支持，RESP3协议，客户端缓存（Client-side caching）。</p></li><li><p style="">Redis7：更细粒度的持久化控制，例如AOF的微秒级时间戳，以及一些命令的改进。</p></li></ul><p style="">对于C++客户端，需要选择支持这些特性的版本。</p><p style=""></p><p style=""></p><p style=""></p><p style=""></p>
